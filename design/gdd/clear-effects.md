# 清除效果与连斩

> **Status**: Revised（2026-10-30，并入切片第四至六版和选将；待重新审查）
> **Author**: 用户 + 主会话（lean 模式）
> **Last Updated**: 2026-10-30
> **Last Verified**: 2026-10-27
> **Implements Pillar**: 1 一回一乐、3 故事决定这一回打什么仗

## Summary

两件“消得更爽”的事。**兵种效果**：消掉一对火，盘上所有营帐一起烧掉（压在底下的也烧）；消掉一对马，所有弓兵冲散；消掉一对水，所有城寨冲垮。**连斩**：连着消对、中间没有连错，就算连斩（不再看时间）；三连斩起，在敌将模式里每次让敌将退 1 步（每轮出手前最多退 2 步），在压境模式里推迟下一次下压，在粮草模式里只是喝彩。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `盘面与连通、对局流程与时钟`

## Overview

清除效果与连斩是规则层里专门制造“释放”的两样东西（支柱 1）。兵种效果把三国名场面（火烧连营、铁骑冲阵、水淹七军）变成盘上一清一大片的瞬间，同时制造“先消哪对”的讲究：把火留到营帐最多的时候，或者别手动把营帐消掉。层叠（切片第六版）让这个瞬间更大：压在底下、玩家够不着的目标兵也一起清掉。连斩奖励**稳**而不是**快**（切片第五版）：连错一次就断，所以它和敌将“按步出手”是同一种节奏，中老年不用抢时间也能打出来。本系统只决定“触发了什么”：效果由本系统通过盘面清掉；连斩的奖励由本系统判定、由战场压力执行（压力持有蓄力步数和下压时间）。兵种效果在回目编排里按名场面逐个登场（支柱 3）。

## Player Fantasy

“一把火，营帐全没了。”玩家忍着不去碰营帐，等营帐攒多了再点火，看着一片营帐被烧光，连压在底下的也翻不出来了；稳稳地一对接一对消，不点错，敌将的蓄力就被一步步逼回去。

## Detailed Design

### Core Rules

**兵种效果**

1. 三种效果兵和它们的目标（效果兵和目标兵种互不重叠，所以效果不会连锁，这是数据不变量）：

   | 效果兵 | 目标 | 名字 |
   |---|---|---|
   | 火 `huo` | 营 `ying` | 火烧连营 |
   | 马 `ma` | 弓 `gong` | 铁骑冲阵 |
   | 水 `shui` | 城 `cheng` | 水淹七军 |

2. **触发**：只有盘面返回的 `match`（玩家消除，含赵云的 `forced` 一对）是效果兵时触发。效果或技能通过 `clearKind`/`clearCells` 清掉的效果兵**不触发**；关羽斩一排、补斩斩到的效果兵也不触发（用户决定 1，2026-10-30）。
3. **结算**（对局流程规则 6 的第 ① 步里判断，按它的分发表执行）：
   - 盘上有目标时（`count(目标) > 0`，**含底牌**）：申请 `effect` 令牌，时长 `EFFECT_HIGHLIGHT_MS`（按前台真实时间计，见对局流程规则 4）。上层的目标块同时高亮，压着目标底牌的格子牌边一起高亮（样式归“界面与交互”），效果走向动画一次扫过。
   - 令牌到点：调用盘面的 `clearKind(目标, 'effect')`。盘面把这种兵**连底牌一起清掉**，上层清掉后底下有别种牌的翻上来；返回 `clear`，`pairs` 含底牌。由对局流程交给战场压力；然后归还令牌。（切片第六版）
   - 被清掉的目标数量（上层加底层）必然是偶数（不变量 I1）。
   - 清除完成后，按对局流程到结算点再检查死局和胜负。所以粮草模式里“消火把粮扣到 0”不会抢在火烧之前判负。
4. **没有目标时**（上层和底层都没有）：这一对效果兵照常消掉；不申请令牌、不锁盘；喊字位用**读的字**（黑体）显示“{目标}已经没了”（例如“营已经没了”），停留时间按喊字位的统一规则（`SHOUT_MS`，见“界面与交互”）。
5. **效果清掉的牌算“非玩家清除”**（盘面的 `clear`，`source = 'effect'`）：在敌将模式里按对数计伤害，**底牌也算**（例如上层 4 块营、底下 2 张营 → 3 对 → 伤害 3）；在粮草模式里不耗粮；不给武将蓄力；不推进敌将步数；不计入连斩，也不打断连斩；不碎拒马。

**连斩**（切片第五版，用户 2026-10-28 批准）

6. **计数**：连斩是“不连错的连续消除”，**不看时间**。
   - 每次 `match`：`combo + 1`，`maxCombo = max(maxCombo, combo)`。
   - 每次 `miss`（连不上）：`combo = 0`。
   - 赵云的 `forced` 一对算玩家消除，`combo + 1`。
   - 下面这些**既不加、也不断**连斩：效果清除、技能清除（关羽斩一排和补斩、诸葛亮清兵）、释放技能本身、关羽选排和取消选排、死局洗牌、敌将出手（含特技、增兵、二阶段切换）、点空格取消选中、换选中。
   - 开局（含“再来一回”）时 `combo = 0`、`maxCombo = 0`。
7. **显示**：`combo ≥ 2` 时显示连斩字：二到十二用汉字“N连斩”（二连斩……十二连斩）；13 以上统一显示“连斩不断”。连线改用朱色。连斩字出在盘上第二块上方一格（不进喊字位，不锁盘）。
8. **奖励**：`combo ≥ COMBO_THRESHOLD` 时，每次 `match` 本系统都调用一次战场压力的 `comboReward()`，由压力按模式执行（数值归本系统）：
   - **敌将反击**（切片第五版）：敌将退 `COMBO_PUSHBACK` 步，最低到 0；两次出手之间累计最多退 `COMBO_PUSHBACK_CAP` 步，敌将出手后（含被赵云挡下、被诸葛亮破掉的那一次）清零。二阶段切换时也清零。`comboReward()` 返回实际退的步数；为 0 时（步数本来是 0，或本轮已退满）什么都不做，否则界面显示“压住一步”。
   - **顺序**：对局流程先通知本系统、再通知战场压力（对局流程规则 6）。所以三连斩起的那一对是“先退 1 步、再因这一对涨 1 步”，净不涨（照切片，用户决定 2026-10-30）；步数为 0 时退不了，这一对照涨 1 步。
   - **敌军压境**：下一次下压推迟 `PRESS_DELAY_MS`；两次下压之间累计推迟最多 `PRESS_DELAY_CAP_MS`，每次下压后清零（压力的 `comboDelay_w`）。连斩改为不看时间后，这一模式的奖励尚未在切片里验证，见 Open Questions。
   - **粮草有限**：不影响规则，只显示连斩字。理由：这一模式的紧张来自“想清楚再动”，奖励手快会和它冲突。
9. **交出**：一回结束时，对局流程读取 `maxCombo` 写进结果对象。

### States and Transitions

| 状态 | 含义 | 进入 | 离开 |
|---|---|---|---|
| 空闲 | 没有效果在结算 | 回合开始；效果结算完成 | 玩家消除一对有目标的效果兵 → 结算中 |
| 结算中 | 持有 `effect` 令牌，目标高亮 | 见上 | 令牌到点 → 清除目标（含底牌）、归还令牌 → 空闲 |

连斩没有独立状态，只有两个数值：`combo`、`maxCombo`。

### Interactions with Other Systems

| 系统 | 方向 | 数据 | 接口归属 |
|---|---|---|---|
| 盘面与连通 | 上游 | 收到 `match`（`kind`、`forced`）和 `miss`；读 `count(目标)`（含底牌）；调用 `clearKind(目标, 'effect')` | 盘面 |
| 对局流程与时钟 | 上游 | 按规则 6 的第 ① 步被通知（先于战场压力）；申请 `effect` 令牌；结束时被读 `maxCombo` | 对局流程 |
| 战场压力 | 下游 | 调用 `comboReward()`；效果的 `clear` 经对局流程交给压力计伤害 | 压力实现 `comboReward` 并持有 `pushedSinceAttack`，数值归本系统 |
| 武将技能 | 单向约定 | 技能清除（含关羽斩一排、补斩）不触发效果、不计也不断连斩；赵云的 `forced` 一对触发效果、计连斩 | 双方都写明 |
| 回目编排与难度 | 下游（数据约定） | 本系统定义效果兵、目标和名字；回目决定每一回放哪些效果兵、哪一回首次登场、目标压多少在底下 | 本系统 |
| 界面与交互 | 下游 | 效果块的双线框和角印、预告圈、高亮（含压着目标的牌边）、连斩字、“压住一步”、喊字 | 本系统提供状态 |
| 进度、三星与存档 | 下游（软） | `maxCombo` 经结果对象传过去，只显示、不评星 | 对局流程 |

## Formulas

The combo_count formula is defined as:

`match` 时 `combo = combo + 1`；`miss` 时 `combo = 0`；其他事件不变

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| combo | int | 0–本回玩家消除总对数 | calculated | 当前连斩数；开局 0 |
| maxCombo | int | 0–本回玩家消除总对数 | calculated | 本回最高连斩 |

**Output Range:** 0 到本回玩家消除总对数（没有上限）；显示上 13 以上统一为“连斩不断”。
**Example:** 消、消、消、错、消、诸葛亮清兵、消 → combo = 1、2、3、0、1、1、2；maxCombo = 3。

The boss_pushback formula is defined as:

`cut = min(COMBO_PUSHBACK, COMBO_PUSHBACK_CAP − pushedSinceAttack, steps)`；`cut > 0` 时 `steps' = steps − cut`、`pushedSinceAttack += cut`（当 `combo ≥ COMBO_THRESHOLD`；敌将出手或换阶段时 `pushedSinceAttack = 0`）

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| steps | int | 0–stepsMax | battle-pressure | 敌将已蓄的步数；一阶段 stepsMax = 8，二阶段 6 |
| COMBO_PUSHBACK | int | 1–2 | data file | 每次连斩奖励退的步数，默认 1 |
| COMBO_PUSHBACK_CAP | int | 1–4 | data file | 两次出手之间累计最多退的步数，默认 2 |
| pushedSinceAttack | int | 0–CAP | battle-pressure | 自上次出手（或开局、换阶段）以来已退的步数 |
| COMBO_THRESHOLD | int | 2–5 | data file | 生效的最低连斩数，默认 3 |

**Output Range:** cut 为 0–COMBO_PUSHBACK；每个出手周期里连斩最多抵掉 COMBO_PUSHBACK_CAP 步。
**Example:** 一阶段 stepsMax = 8，steps = 5。第 3 连斩：退到 4，再因这一对涨到 5；第 4 连斩：退到 4、涨到 5（本轮已退 2）；第 5 连斩：cut = 0，涨到 6。一路不连错时，这一轮要消 10 对吕布才出手（8 + 2），而不是 8 对。

The press_delay formula is defined as:

`delay = min(PRESS_DELAY_MS, PRESS_DELAY_CAP_MS − comboDelay_w)`；`nextPush += delay`；`comboDelay_w += delay`（当 `combo ≥ COMBO_THRESHOLD` 且盘面还会被下压）

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| nextPush | float | gameTime–∞ | battle-pressure | 下一次下压的游戏时间 |
| PRESS_DELAY_MS | int | 0–2000 | data file | 每次推迟，默认 1000 |
| PRESS_DELAY_CAP_MS | int | 0–6000 | data file | 两次下压之间累计推迟上限，默认 3000 |
| comboDelay_w | int | 0–PRESS_DELAY_CAP_MS | battle-pressure | 距上次下压以来已推迟的量，每次下压后清零 |

**Output Range:** 两次下压之间最多推迟 PRESS_DELAY_CAP_MS。
**Example:** 间隔 6000 ms，两次下压之间打出 3、4、5、6 连斩 → 推迟 1000、1000、1000、0 → 这一段共 9000 ms。

## Edge Cases

- **如果效果把盘上最后的牌全部清掉**（含底牌）：到结算点由战场压力判断（敌将判胜或进入二阶段、粮草判胜；压境立刻下压下一行或判胜，见“战场压力”）。
- **如果目标只剩底牌、上层一块都没有**：仍算“有目标”，申请令牌，只高亮压着目标的格子，到点照样清掉；`clear.cells` 为空、`buried` 为张数、`pairs` 照算。切片代码只看上层（只剩底牌时显示“已经没了”），正式版按本条，见 Open Questions。
- **如果被清掉的目标上层格底下压着别种牌**：那张翻上来，成为新的上层；它可能正好和别处凑成一对，这是层叠的乐趣，不额外处理。
- **如果粮草模式 food = 1 时玩家消掉一对火、盘上剩下的全是营**：消火扣粮到 0（压力规则），火烧清掉全部营，到结算点盘已空 → 判胜。
- **如果效果演出期间切后台**：`effect` 令牌计时暂停，回来点“接着讲”后走完剩下的时间再清除。
- **如果连斩中间隔了很久、或跨过一段演出、或跨过敌将出手**：连斩照样延续，只有连错会断（规则 6）。
- **如果连斩中间放了技能**（包括关羽斩一排、诸葛亮清兵、张飞、赵云）：连斩不变，技能清掉的对数不加连斩。
- **如果关羽进入选排后取消**：连斩不变。
- **如果连斩达到奖励时正好也触发了效果**：连斩奖励在第 ① 步立即执行；效果在之后的令牌里执行。喊字位只有效果名（连斩奖励没有喊字）。
- **如果敌将步数已是 0**：`comboReward()` 返回 0，不显示“压住一步”；这一对照常让敌将涨 1 步。
- **如果敌将正被张飞震慑**（这几步不涨）：连斩照样能退步；退到 0 为止。
- **如果本轮已退满 `COMBO_PUSHBACK_CAP`**：返回 0，不显示“压住一步”，直到下一次出手。
- **如果效果兵的另一块被技能清掉**：不触发效果（规则 2）。由于不变量 I1，盘上不会留下单独的一块效果兵（含底牌）。
- **如果同一种效果兵在一回里出现两对**（压境的新行、敌将增兵会按权重抽到效果兵，层叠也会把第二对压在底下）：每消一对触发一次；第二次多半没有目标，显示“营已经没了”。
- **如果目标块有十几块**：同时高亮，走向动画一次扫过，不逐块排队。

## Dependencies

- **依赖（上游）**：盘面与连通（硬：`match`、`miss`、`count`、`clearKind`）、对局流程与时钟（硬：通知顺序、`effect` 令牌）。
- **被依赖（下游）**：战场压力（硬：`comboReward()`、效果的伤害）、界面与交互（硬：效果块状态、连斩字、“压住一步”）、回目编排与难度（数据：效果兵与目标的定义）、进度三星与存档（软：最高连斩只显示）。
- 与“武将技能”的关系是**单向约定**：技能清除不触发效果、不计也不断连斩，由本系统的规则 2、5、6 保证，双方都写明。

## Tuning Knobs

| 名称 | 默认 | 安全范围 | 调高 | 调低 | 相互影响 |
|---|---|---|---|---|---|
| COMBO_THRESHOLD | 3 | 2–5 | 奖励太难拿 | 随手就退步，敌将没威胁 | 失败提示文案引用它（见“回目编排与难度”） |
| COMBO_PUSHBACK | 1 | 1–2 | 2 时连斩的那一对净退 1 步，敌将被压得太死 | — | 受累计上限约束；和每对涨 1 步（战场压力）一起看 |
| COMBO_PUSHBACK_CAP | 2 | 1–4 | 稳手玩家能把吕布拖得很久 | 连斩对敌将几乎没用 | 默认下不连错时一阶段每轮要消 10 对才出手（8 + 2）；切片模拟见 DESIGN-v5/v6 |
| PRESS_DELAY_MS | 1000 | 0–2000 | 压境变松 | 稳手没回报 | 受累计上限约束 |
| PRESS_DELAY_CAP_MS | 3000 | 0–6000 | 熟手可以拖得很久 | 奖励很快封顶 | — |
| EFFECT_HIGHLIGHT_MS | 380 | 200–600 | 拖慢节奏 | 看不清清掉了哪些 | 时钟在这段时间暂停 |

## Visual/Audio Requirements

依据美术圣经第 2 节⑦、第 3 节“效果块”、第 7 节：

- 效果块用双线框（外朱内墨），画在块**里面**；右下角放一枚 ≥ 22 px 的朱色角印，印里阴刻目标兵的剪影。盘上（含底牌）已经没有目标时，角印显示成虚线。
- 预告圈：选中效果块 150 ms 后，所有上层目标块上一起出现朱色虚线内圈（画在块里面、贴着图标）；150 ms 内就点了第二块则不出现；取消选中或配对后立刻消失，配对成功时原地变成朱勾。预告圈不透露底牌。
- 效果走向：火是朱墨火苗沿目标扫过；马是墨色飞白横向冲过；水是淡墨卷浪由下往上漫过。不加遮罩，只在盘面局部提亮。
- 效果名写在亮纸横幅上，用深朱毛笔字，≤ 4 字，放在喊字位。
- 连斩：深朱毛笔字加亮纸硬描边，出在第二块上方一格，进 100、停 500、退 100 ms；不震屏。
- 敌将模式的退步：敌将蓄力圆点旁显示“压住一步”（落点见“界面与交互”）。
- 音效（完整版）：火苗、马蹄、水声，连斩时有一声喝彩。

`art-director` 未单独咨询（lean 模式）；以上取自美术圣经。

## Game Feel

- 效果结算的 380 ms 是“看清楚自己干了什么”的时间，时钟在这段时间暂停，不扣玩家的压力时间。
- 连斩反馈必须即时：第二对消除的同一帧就出“二连斩”；连错的同一帧连斩字消失。
- 三种模式的连斩奖励都对准该模式的紧张点：敌将是“他快出手了”，压境是“快压到底了”，粮草模式里不给奖励。
- 连斩奖励的是“不点错”，不是“手快”：老人慢慢想、看准了再点，同样拿得到。

## UI Requirements

效果块的双线框、角印、预告圈，效果名横幅，连斩字，“压住一步”提示，压着目标的格子在高亮时的牌边。见“界面与交互”的反馈落点表。

## Acceptance Criteria

- **GIVEN** 盘上上层有 6 块营，**WHEN** 玩家消掉一对火，**THEN** 申请 `effect` 令牌 380 ms，期间 `gameTime` 不变、盘锁住；到点后 6 块营全部消失，盘面仍满足 I1。
- **GIVEN** 盘上上层 4 块营、底下压着 2 张营，**WHEN** 玩家消掉一对火，**THEN** 到点后上层和底下都没有营，`clear.pairs = 3`；被清掉的上层格底下若有别种牌，已翻上来。
- **GIVEN** 盘上营只剩 2 张底牌，**WHEN** 玩家消掉一对火，**THEN** 申请 `effect` 令牌，到点后两张底牌被清掉，`pairs = 1`，不显示“营已经没了”。
- **GIVEN** 盘上（含底牌）没有城，**WHEN** 玩家消掉一对水，**THEN** 这一对水消掉，喊字位显示“城已经没了”，不申请令牌。
- **GIVEN** 诸葛亮的技能清掉了全部火，**WHEN** 清除完成，**THEN** 营不受影响（效果不连锁）。
- **GIVEN** 关羽斩一排斩到一对马，**WHEN** 清除完成，**THEN** 弓不受影响，`combo` 不变。
- **GIVEN** 赵云待命（压境或粮草模式），**WHEN** 强制消除一对马，**THEN** 所有弓（含底牌）被清掉，`combo` 加 1。
- **GIVEN** 敌将模式 hp = 12，**WHEN** 火烧掉上层 4 块营和底下 2 张营，**THEN** 敌将 hp 因效果减少 3（加上火这一对本身的 1，共减 4）。
- **GIVEN** 粮草模式 food = 8，**WHEN** 火烧掉 6 块营，**THEN** food 只因火这一对减 1，变为 7。
- **GIVEN** 火烧清掉 3 对营，**WHEN** 清除完成，**THEN** 所有武将的蓄力不变，敌将步数不因清除改变，`combo` 不变。
- **GIVEN** 玩家依次：消、消、消、连错、消，**WHEN** 计算，**THEN** combo 依次为 1、2、3、0、1，maxCombo = 3。
- **GIVEN** combo = 2，**WHEN** 玩家停 30 秒不动后再消一对，**THEN** combo = 3（不看时间）。
- **GIVEN** combo = 4，**WHEN** 玩家放出诸葛亮（清掉 4 对）、再消一对，**THEN** combo = 5。
- **GIVEN** combo = 3，**WHEN** 敌将出手（普通、特技或被挡），**THEN** combo 仍为 3。
- **GIVEN** combo = 5，**WHEN** 一次连不上，**THEN** combo = 0，连斩字消失。
- **GIVEN** 敌将模式一阶段 steps = 5、本轮未退过，**WHEN** 打出第 3、4、5 连斩，**THEN** 每次消除后的 steps 依次为 5、5、6（前两次 `comboReward()` 各返回 1 并显示“压住一步”，第三次返回 0）。
- **GIVEN** 敌将模式 steps = 0，**WHEN** 第 3 连斩，**THEN** `comboReward()` 返回 0，不显示“压住一步”，这一对后 steps = 1。
- **GIVEN** 本轮已退 2 步，**WHEN** 敌将出手，**THEN** `pushedSinceAttack = 0`、steps = 0；**WHEN** steps 回到 1 以上后再打出三连斩以上，**THEN** `comboReward()` 返回 1。
- **GIVEN** 敌将模式 combo 将变为 2，**WHEN** 消除，**THEN** 不调用 `comboReward()`。
- **GIVEN** 压境模式本段已推迟 2500 ms，**WHEN** 又一次三连斩以上的消除，**THEN** 只推迟 500 ms，本段累计 3000 ms；**WHEN** 下压发生，**THEN** 累计清零。
- **GIVEN** 粮草模式，**WHEN** 打出五连斩，**THEN** 粮数、规则都不变，只显示“五连斩”。
- **GIVEN** combo 从 12 变为 13，**WHEN** 显示，**THEN** 连斩字为“连斩不断”。
- **GIVEN** “再来一回”，**WHEN** 开局，**THEN** combo = 0、maxCombo = 0。

## Open Questions

- 连斩改为不看时间后，压境模式的推迟奖励（按时间下压）还合不合适？稳手玩家每段都能拿满 3000 ms。第五版只在敌将模式验证过。（负责：关卡设计做压境回目时；目标：第二、三回重排前。）
- 目标只剩底牌时是否触发效果：本文按“触发并清掉”写（与切片第六版“连底牌一起清”一致），切片代码只看上层。需用户确认。（负责：用户。）
- 中老年能打出三连斩的比例是多少？不看时间后应该明显变高；如果三连斩太常见，退步上限 2 是否仍够让吕布有威胁？（负责：试玩；目标：调参前。）
