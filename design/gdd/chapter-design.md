# 回目编排与难度

> **Status**: Revised（2026-10-30，并入切片第四至六版和选将；并入正式版前 10 回关卡（用户 2026-10-30 批准）；待重新审查）
> **Author**: 用户 + 主会话 + 关卡设计（lean 模式）
> **Last Updated**: 2026-10-30
> **Last Verified**: 2026-10-27
> **Implements Pillar**: 3 故事决定这一回打什么仗（主）、4 一看就会（“一回只教一样新东西”从正式版第 1 回起执行）

## Summary

每一回是一份数据：回目号和标题、盘面大小（行数和列数）、兵种组成、用哪种压力和它的参数、技能槽和主将、推荐阵容、赢了解锁谁、哪个兵种效果第一次登场、敌将和台词、下回预告。正式版前 10 回走蜀汉一路，按故事顺序排：从破黄巾到定军山，三种压力轮流出现，6 位武将一回一回攒起来（规则 13）。本系统定义数据格式、加载时的合法性检查和难度怎么排，不含任何运行逻辑。

> **Quick reference** — Layer: `Feature` · Priority: `MVP` · Key deps: `盘面与连通、清除效果与连斩、战场压力、武将技能、选将与解锁`

## Overview

回目编排把三国故事落到玩法上（支柱 3）：吕布是三国第一猛将，所以虎牢关、白门楼打“敌将反击”；过五关、长坂坡是闯关、被追，所以打“敌军压境”；徐州、博望坡缺粮、要算计，所以打“粮草有限”。兵种效果按名场面登场（火烧博望、长坂坡铁骑）。数据和规则分开：所有回目写在一个数据文件里，规则系统只读不写，调参不用改代码。加载器在开局前检查每一回的数据，不合法的回目不进游戏。“一回只教一样新东西”（支柱 4）从正式版第 1 回起执行，例外写在规则 12 和“选将与解锁”规则 4。

## Player Fantasy

“下回分解。”每打完一回，结算卡上写着下一回的标题，玩家想知道白门楼怎么擒吕布、长坂坡怎么救阿斗，于是再来一回。

## Detailed Design

### Core Rules

**数据格式**

1. 数据文件里有四部分：`chapters`（回目数组，数组顺序就是书目里的顺序，竖切片起也是解锁顺序；MVP 包全开，见“进度、三星与存档”规则 8）、`enemies`（敌将表）、`texts`（各模式的通用文字）、`starters`（开局就有的武将 id 列表，见“选将与解锁”规则 6）。所有兵种用“盘面与连通”规则 2 的 id 作键，武将用“武将技能”规则 1 的 id。正式版 `starters = [guan_yu]`（用户决定，2026-10-30）。
2. 每一回的字段：

   | 字段 | 必填 | 说明 |
   |---|---|---|
   | `id` | 是 | 稳定的存档键，例如 `ch01`。上线后不能改 |
   | `no`、`title` | 是 | 回目号和标题，例如“第一回”“斩黄巾英雄首立功” |
   | `mode` | 是 | `press` / `food` / `boss` |
   | `rows` | 是 | 行数 6–8；压境必须是 8 |
   | `cols` | 否 | 列数 5 或 6，缺省 6。正式版默认按 5 列编排（大棋子，手机上 66–72 px；用户决定，2026-10-30） |
   | `deck` | 是 | `{兵种 id: 块数}`，块数为偶数。满盘模式（敌将、粮草）可以多于格数，多出来的背面朝下压在格子底下（层叠，见“盘面与连通”）；压境只描述开局的那几行，不叠 |
   | `pool` | 否 | `{兵种 id: 权重}`，压境新行和敌将增兵按它抽对；缺省为 `deck` 里各兵种的对数 |
   | `press` | 压境必填 | `{startRows, waves, interval, waveList?}`；`waveList` 写死每一波，长度必须等于 `waves`，每项是 `cols` 个元素，每个元素是兵种 id、`null`（空格）或 `'jm'`（拒马）。兵恰好 `floor(cols/2)` 对（“战场压力”规则 8）；兵之外的位置（5 列时 1 格）写 `null` 或 `'jm'`，拒马只能占这个空格位（用户决定 4，2026-10-30） |
   | `food` | 粮草必填 | `{slack}` |
   | `boss` | 敌将必填 | `{enemy, hp?, steps, hearts, addPairs, phase2?}`。`enemy` 是 `enemies` 表里的 id；`hp` 是第一段血，缺省为开局盘上的对数；`steps` 是敌将走满几步出手（玩家连上一对走 1 步、连错走 2 步，见“战场压力”）；`phase2` 是可选的第二段 `{hp, steps, name?, shout?, lines?, specials?}`：第一段血打空后进入，`name` 是二阶段名（例如“暴怒吕布”），`shout` 是转阶段横幅（例如“吕布暴怒！”），`lines` 换掉台词，`specials` 是二阶段特技的轮换顺序（特技 id 列表，缺省为吕布的三种 `[sweep, charge, roar]`，即“战场压力”的 `SPECIALS`）。有 `phase2` 时敌将才有特技（“战场压力”） |
   | `foe` | 否 | 压境、粮草模式里写在水牌上的敌方名字（只显示），例如“曹军（虎豹骑）” |
   | `slots` | 是 | 技能槽数 1–3（“选将与解锁”规则 1） |
   | `lead` | 是 | 主将的武将 id，占第 1 个槽，不能换（“选将与解锁”规则 2） |
   | `recommend` | 是 | 推荐阵容，武将 id 列表，长度等于 `slots`，第一位必须是 `lead`（“选将与解锁”规则 3）。取代原来的 `generals`；出阵武将由选将系统在开讲时给出，最多 3 位 |
   | `unlock` | 否 | 第一次赢下这一回时解锁的武将 id（“选将与解锁”规则 5） |
   | `need` | 否 | 整数（全员同一个）或 `{武将 id: 整数}`；范围 1–4。缺省按武将：关羽 2、张飞 3、赵云 3、诸葛亮 4、刘备 3、黄忠 3（快慢档，切片第五版，用户 2026-10-28 批准；刘备、黄忠用户 2026-10-30 定） |
   | `newEffect` | 否 | 本回第一次登场的效果兵 id；水牌上加一行规则说明 |
   | `enemyLines` | 否 | 敌将出手时轮流说的台词，每句 ≤ 8 字（含标点）；缺省用 `enemies` 表里的 |
   | `ruleLine` | 否 | 水牌上的压力规则一句话；缺省用 `texts.ruleLine[mode]` |
   | `failHint` | 否 | `{失败原因: 文字}`，覆盖 `texts.failHint` 里同一原因的那一句；没写到的原因用缺省 |
   | `preview` | 否 | 赢了之后的预告；缺省为“下回：”加下一个能加载的回目的标题；最后一回缺省为“全书未完，下回分解” |
   | `stars` | 否 | 三星阈值覆盖，形状由“进度、三星与存档”定义 |

3. `enemies` 表：`{id: {name, lines, specialNames?}}`。头像资源按 id 取。`specialNames` 是 `{特技 id: 显示名}`，覆盖特技的缺省显示名（`sweep` 画戟横扫、`charge` 赤兔冲阵、`roar` 虎啸、`chain` 铁索连环；缺省名归“战场压力”）。预告“下招：××”、出手横幅、诸葛亮的“破××”都读显示名。同一机制换名字时，盘上的东西样子不变（例如夏侯渊的“布鹿角”放下的仍是拒马）。

   | id | name | lines（一阶段，每句 ≤ 8 字） | specialNames |
   |---|---|---|---|
   | `lv_bu` | 吕布 | “人中吕布！”“谁敢挡我！” | 不写（用缺省名） |
   | `wen_chou` | 文丑 | “河北文丑在此！”“公孙瓒休走！” | 不写（文丑只一段血，没有特技） |
   | `cao_cao` | 曹操 | “八十三万大军！”“对酒当歌！” | `{chain: '铁索连环'}` |
   | `xiahou_yuan` | 夏侯渊 | “吾乃夏侯妙才！”“三日行五百！” | `{charge: '布鹿角'}`（虎啸不改名） |

4. `texts`：
   - `ruleLine.press`：“敌军每 {interval 秒} 秒压下一排，最下一排有兵时再压就破城”
   - `ruleLine.food`：“每消一对耗一份粮，连不上也扣，粮尽就输”
   - `ruleLine.boss`：“{enemy}走满 {steps} 步就出手，{hearts} 颗心没了就输”（`{enemy}` 是敌将名，`{steps}` 是第一段的步数）
   - `effectLine.huo` / `ma` / `shui`：“火烧连营：消一对火，烧掉所有营”“铁骑冲阵：消一对马，冲散所有弓”“水淹七军：消一对水，冲垮所有城”（水牌上 `newEffect` 那一行）
   - `failHint.破城`：“最下一排快满时，试试关羽”
   - `failHint.粮草断绝`：“营、弓、城别手动消，留给火、马、水”
   - `failHint.城破`：“连着消、不连错，{COMBO_THRESHOLD} 连斩起能让{enemy}退步”
   - 回目自己的 `failHint`（规则 2）：第六回 `{破城: '关羽斩排能破拒马'}`；第十回 `{城破: '先蓄黄忠，再消马'}`（用户决定 6）。
   - 花括号里的值在显示时从参数代入，所以改参数不用改文字。秒数是整数时不带小数（“7”），否则保留一位（`slow=1` 时 9100 显示“9.1”）；步数总是整数。水牌显示的是实际生效的值（乘过 `slow` 倍率之后）。
   - `skillLine[武将 id][mode]`：水牌上出阵武将旁的一行技能说明（用户决定，2026-10-27），每行 ≤ 12 字：

     | 武将 | 敌将 | 压境 | 粮草 |
     |---|---|---|---|
     | 关羽 | 点选一排，整排斩掉 | 点选一排，整排斩掉 | 点选一排，整排斩掉 |
     | 张飞 | 敌将退三步，三步不涨 | 底排有兵时，吓退一次 | 抢回三份粮 |
     | 赵云 | 挡下敌将下一招 | 下一对同种兵必消 | 下一对同种兵必消 |
     | 诸葛亮 | 清最多的兵，破下一个特技 | 清掉最多的那种兵 | 清掉最多的那种兵 |
     | 刘备 | 补一颗心，众将各蓄一格 | 众将各蓄一格 | 补两份粮，众将各蓄一格 |
     | 黄忠 | 点选一列，整列射穿 | 点选一列，整列射穿 | 点选一列，整列射穿 |

     文字以“武将技能”规则 18 为准（那边定文字，这里只存字段）。刘备粮草那一行的“两份”从 `LIU_FOOD` 代入；“一颗”“一格”固定。

     （关羽、张飞、赵云、诸葛亮的敌将模式说明按切片第五版和用户决定 1，2026-10-30；赵云在压境、粮草里暂保留旧技能，用户决定 6。刘备、黄忠按用户决定 3、5，2026-10-30。）
     张飞压境那一行 14 字，超过 12 字的上限（沿用原文），见 Open Questions。
   - 水牌上的敌方名：敌将模式取 `enemies[boss.enemy].name`，其他模式取 `foe`（没有就不显示）。
5. 发牌种子不在回目数据里，由对局流程给出（见“对局流程与时钟”规则 12）。

**加载与合法性检查**（游戏启动时对每一回执行一次）

6. **拒绝加载**（这一回不进游戏）：
   - `deck` 里有单数，或出现不认识的兵种 id；
   - `cols` 不是 5 或 6；
   - 不满足“盘面与连通”的 deck_valid：满盘模式（敌将、粮草）要 `rows × cols ≤ Σ deck ≤ rows × cols × (1 + STACK_DEPTH)`（`STACK_DEPTH` = 1，每格最多压一张）；压境 `Σ deck = startRows × cols`（压境不叠）。5 列时 `startRows` 只有 4 能过这一条（3 行、5 行是 15、25 块，单数，必然有一种兵是单数）；
   - `rows` 不在 6–8，或压境的 `rows ≠ 8`；
   - `mode` 对应的参数缺失，或超出“战场压力”变量表里的 Range（敌将模式：`steps` 3–15、`hearts` 1–5、`addPairs` 0–4、`hp` 1 到 `Σ deck / 2`；`phase2` 有写时 `hp` 1–60、`steps` 3–15）；
   - `phase2.specials` 写了但是空列表，或含不认识的特技 id（合法：`sweep`、`charge`、`roar`、`chain`）；
   - `pool` 为空、含不认识的 id，或有不是正整数的权重；
   - `waveList` 长度不等于 `press.waves`，或某一项不是 `cols` 个元素，或含不认识的 id（兵种 id、`null`、`'jm'` 之外的），或兵的块数不等于 `2 × floor(cols/2)`（5 列时 4 块兵 + 1 个 `null` 或 `'jm'`；6 列时 6 块兵，没有空格位，写 `'jm'` 就少了兵，一定拒绝），或某种兵在一项里是单数块（会破坏盘面的偶数不变量）；
   - 敌将模式的 `boss.enemy` 不在 `enemies` 表里；
   - `enemies` 里某个 `specialNames` 的键不是合法特技 id；
   - `slots` 不在 1–3；`lead` 缺失或不认识；`lead` 的蓄力兵不在 `deck` 里（主将必须能放技能）；
   - `recommend` 长度不等于 `slots`、第一位不是 `lead`、含不认识或重复的武将 id；
   - `unlock` 或 `starters` 含不认识的武将 id；
   - `need` 不在 1–4；
   - `id` 重复（第二个起拒绝）。
7. **只警告**（照常加载）：
   - 推荐阵容里的武将，蓄力兵在 `deck` 里少于 `need` 对；蓄力兵根本不在 `deck` 里的推荐武将，填槽时跳过（“选将与解锁”Edge Cases）；
   - `unlock` 写了一位已在 `starters` 里的武将，或两回的 `unlock` 是同一位武将（以先赢下的那一回为准）；
   - 有效果兵却没有它的目标兵（例如有火没有营）；
   - `newEffect` 写的兵种不在 `deck` 里（水牌上不显示这一行）；
   - 参数超出“战场压力”Tuning Knobs 的安全范围；
   - 标题超过 12 字、台词超过 8 字、特技显示名超过 4 字；
   - `failHint` 覆盖的键不是已知的失败原因（破城、粮草断绝、城破），这一项不显示；
   - `stars` 覆盖里的 `foodT3`、`missT2` 超出 0–6（“进度、三星与存档”规则 3 的安全范围）。
8. **`stars` 阈值写错**（形状不对、t3 比 t2 宽松等）：开发版报错；正式版忽略这项，用缺省阈值（与“进度、三星与存档”一致）。
9. 开发版对任何拒绝和警告都在控制台给出回目 `id` 和字段名，被拒绝的回目同样不进游戏；正式版把拒绝的回目从列表里拿掉并写日志。“下一回”和缺省预告都按**能加载的**回目顺序算，不会指向被拿掉的回目。`need` 写成对象时，没写到的武将用他自己的缺省值（关羽 2、张飞 3、赵云 3、诸葛亮 4、刘备 3、黄忠 3）；写成整数时全员同一个。新武将的缺省值由“武将技能”给出。

**难度怎么排**

10. 难度有四根杠杆：压力参数（压境 `interval`、敌将 `steps` 和 `phase2.steps`、粮草 `slack`）、对数（盘的大小、层叠压了几张、压境的波数）、新东西的数量（新效果、新压力、新武将、新敌将）、技能槽数 `slots`。它们各自影响多大，要靠试玩测出来；先用公式和模拟脚本估算（round_length、boss_pace、战场压力的 press_deadline）。层叠增加的难度在“找对子更难、更容易连错”，模拟脚本量不出来，只能靠试玩（切片第六版）。
11. 一种压力第一次出现时取温和的一档，之后同一种压力再出现时再收紧。5 列版的收紧顺序（2026-10-30，取代按 6 列写的 7 → 6.5 → 6 秒）：
    - **压境 `interval`**：三回都是 12000（合法上限）（模拟后用户 2026-10-30 定）。原定 10000 → 8000 → 7000，模拟里每步 4 秒、连错两成用技能只赢 54% / 3% / 0%；12000 时 80% / 78% / 69%。5 列开局只能 4 行，输局都在第 4–5 次下压，波数不影响胜负，所以压境回之间的难度靠盘面内容拉开（第六回拒马，第八回弓和马），不靠间隔。每步 5 秒的玩家靠慢速档（× 1.3）：71–83%。
    - **敌将一阶段 `steps`**：8（吕布，第二回）→ 8（文丑，第三回）→ 6（吕布，第五回）→ 7（曹操，第九回）→ 7（夏侯渊，第十回）；**二阶段**：5（吕布）→ 6（曹操）→ 6（夏侯渊）。第十回原定 6 / 5，模拟里连错两成只赢 26%，改为 7 / 6、二阶段血 24 → 18（模拟后用户 2026-10-30 定）。
    - **粮草 `slack`**：3（第四回）→ 2（第七回）。
    - 心一律 3 颗。吕布第五回比曹操紧，是用户的指定（“吕布还可以再难一点”，2026-10-30 用户决定 4），故事上也说得通：吕布是猛将，曹操是谋主。难度和爽感来自连斩退步和技能，而不是放水。
12. 正式版起执行“一紧一松”：紧的一回之后跟一回松的或中的，并且每一回只引入一样新东西（支柱 4）。强度 1–5 是按“估算挂几颗心、盘面余量、新东西的分量”给的，不是测出来的：

    | 回 | 压力 | 松紧 | 强度 | 理由 |
    |---|---|---|---|---|
    | 1 | 压境 | 松（教学） | 1 | 完全新手要能赢：下压 10 秒一次，只有关羽 |
    | 2 | 敌将 | 中 | 2 | 第一次敌将，取温和档 8 步、一段血 |
    | 3 | 敌将 | 松 | 2 | 新东西是层叠，压力不加：8 步、一段血、3 颗心加护盾 |
    | 4 | 粮草 | 松 | 2 | 新压力粮草，`slack` 3 |
    | 5 | 敌将 | **紧** | 4 | 吕布两段血 6 / 5 步（用户指定） |
    | 6 | 压境 | 中 | 3 | 紧接第五回，按“中”排（用户决定 8）：间隔比第一回紧，开局缓冲不变 |
    | 7 | 粮草 | 松 | 2 | 新效果火，`slack` 2，诸葛亮初登场 |
    | 8 | 压境 | **紧** | 4 | 压境 7 秒、10 波，最长的一回压境 |
    | 9 | 敌将 | 中 | 3 | 新敌将曹操，7 / 6 步 |

## Formulas

The round_length formula is defined as（设计时估算一回用时，不在加载时计算）:

- 敌将：`T ≈ (hp + phase2.hp − E) / r`。敌将按步出手，不限时，所以 `T` 只是用时估算，输赢由 boss_pace 决定
- 压境：`T ≈ (P − E) / r`，其中 `P = startRows × cols / 2 + waves × floor(cols / 2)`（2026-10-30 改，用户决定 15：原式 `(startRows + waves) × cols / 2` 在单数列上多算，5 列每波只有 2 对）。盘一清空就立刻下压下一波（战场压力规则 10），所以手快的人不会干等；`T` 不能超过 `T_max = (waves + 8) × interval`，并且每一行都有自己的破城期限（战场压力的 press_deadline）
- 粮草：`T ≈ (pairs − wipePairs) × t_think`

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| r | float | 0.15–1.0 对/秒 | playtest | 玩家的手消速度；开发者约 0.5，目标人群未测 |
| t_think | float | 2–6 秒 | playtest | 粮草模式里每消一对的时间。粮草不限时、要先想再动，所以比限时模式慢，暂取 4 |
| E | int | 0–20 | design estimate | 效果和技能大约清掉的对数，由设计者按 deck 估，不由程序计算 |
| P | int | 16–40 | calculated | 压境一回的总对数；5 列、`startRows` 4 时 `P = 10 + 2 × waves` |
| r_need | float | 0.15–0.45 对/秒 | calculated | 压境稳态要的手速 `1000 × floor(cols/2) / interval` |
| hpMax、pairs、wipePairs | int | — | calculated | 见“战场压力” |

**Output Range:** 目标 60–180 秒。超出时只记在下面的估算表里，调参时处理。
**Example**（关键回；数值未模拟）：

| 回目 | 估算 | 说明 |
|---|---|---|
| 第一回（压境） | `P = 10 + 6 × 2 = 22`，`E ≈ 4`（关羽 2 刀 × 2 对），`r_need = 0.20`，`T_max = 14 × 10 = 140` 秒。r = 0.5：`18 / 0.5 = 36` 秒，盘空立刻下压，约 40–55 秒。r = 0.2：`90` 秒 < 140，80 秒时已清约 16 对加关羽 2 刀，够清开局 10 对（开局 4 行的破城期限是第 5–8 次下压，即 50–80 秒）。r = 0.15：`120` 秒，开局几行偏紧，要靠关羽救底排和连斩推迟 | r ≥ 0.15 基本能赢；手快的人低于 60 秒，是给新手的，先试玩（用户决定 14） |
| 第五回（敌将） | hp 12 + 18 = 30，`E ≈ 8`（一阶段关羽一刀连底牌约 3；二阶段补满援军后再蓄一刀约 5）。r = 0.4：`22 / 0.4 = 55` 秒，加暴怒和出手演出、找对子（压底 14 张），约 70–100 秒 | 进入目标 |
| 第八回（压境） | `P = 10 + 10 × 2 = 30`，`E ≈ 8`（马等弓攒到 3 对再冲约 3、关羽 2 刀 4、赵云约 1），`r_need = 0.29`，`T_max = 18 × 7 = 126` 秒。r = 0.5：`44` 秒；r = 0.35：`63` 秒；r = 0.25：`88` 秒 < 126，但稳态每秒落后 0.04 对，波次阶段（70 秒）累计落后约 3 对，靠开局 4 空行和张飞撑住 | 全书最紧的压境；马一来就消的人 E 少 2–3 对，底排更早告急 |
| 第十回（敌将） | hp 16 + 18 = 34（原 40，模拟后下调），`E ≈ 18`（一阶段黄忠一箭约 6、马冲弓约 2；二阶段火 3–4、诸葛亮 4–5、黄忠第二箭约 2）。r = 0.35：`22 / 0.35 ≈ 63` 秒，加演出和找对（压底 21 张），约 90–120 秒 | 全书最长，作收官 |

第二回（hp 15、单段、不叠）约 40–60 秒，偏短，作为第一次敌将可以接受（用户决定 14，先试玩）。

The boss_pace formula is defined as（敌将模式里每一段大约挨几次出手；切片第五版起按步计，手速不再决定输赢）:

`attacks_i ≈ floor((M_i × STEP_MATCH + X_i × STEP_MISS − B_i − Z_i) / steps_i)`，挨打 `= Σ attacks_i − shields`，挨打 ≥ `hearts` 就输

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| i | int | 1–2 | data file | 第几段血；转二阶段时蓄力清零，分开算 |
| M_i | int | 0–30 | calculated | 这一段里手消的对数 ≈ `hp_i − E_i`（效果和技能清掉的不走步） |
| X_i | int | 0–∞ | playtest | 这一段里连错的次数；连错率 `m = X / (M + X)` |
| B_i | int | 0–2 × 出手次数 | calculated | 连斩退的步数：三连斩起每次退 1 步，每轮出手前最多退 2 步（“战场压力”） |
| Z_i | int | 0–6 × 张飞放的次数 | calculated | 张飞一吼退 3 步，震慑的 3 步也不涨（按 6 步计） |
| steps_i | int | 3–15 | data file | `boss.steps`、`phase2.steps`（`slow=1` 时 × 1.5） |
| shields | int | 0–2 | calculated | 赵云护盾挡下的出手次数；刘备补回的心另算（补 1 颗等于少挨 1 次） |

**Output Range:** 挨打次数 0 到若干次；`hearts` = 3 时挨 3 次就输。只有普通出手扣心，二阶段的特技不扣心（“战场压力”），所以上式在二阶段要只数普通出手（约一半）。
**Example**（`slow` 关；数值未模拟）：
- **第二回**（吕布，hp 15，steps 8，单段）：`E ≈ 3`（关羽一刀），`M ≈ 12`。用技能、连错一成（X ≈ 1）：`12 + 2 − 2 − 6 = 6` → 0 次，3 星。用技能、连错两成（X ≈ 3）：`10` → 1 次。不用技能、连错三成（M 15，X ≈ 6）：`15 + 12 − 4 = 23` → 2 次，剩 1 心，还能赢。
- **第五回**（吕布，6 / 5 步）：一阶段 `M1 ≈ 9`，二阶段 `M2 ≈ 13`。用技能、连错两成：一阶段 `9 + 4 − 2 − 6 = 5` → 0 次；二阶段 `13 + 7 − 4 − 6 = 10` → 2 次（1 特技、1 普通），盾挡普通 → 丢 0–1 心。不用技能、连错两成：一阶段 `12 + 6 − 2 = 16` → 2 次，丢 2 心；二阶段 `18 + 9 − 4 = 23` → 4 次，其中普通 2 次 → 输。切片模拟（四将全上）：6 / 5 步、偶尔连错时用技能胜率 83%，不用 28%（DESIGN-v6）；三将阵容要重跑。
- **第十回**（夏侯渊；下面是原定 6 / 5 步、血 16 + 24 时的估算，模拟后已改为 7 / 6、16 + 18，见 Open Questions 的模拟结果）：一阶段 `E1 ≈ 8`、`M1 ≈ 8`，连错两成 `X ≈ 2`：`8 + 4 − 2 = 10` → 1 次，盾挡 → 0 心。二阶段 `E2 ≈ 10`、`M2 ≈ 14`，`X ≈ 3.5`：`14 + 7 − 4 = 17` → 3 次（特技、普通、特技）→ 丢 1 心。不用技能：输。先消马的人黄忠蓄不满，`E1` 少约 6 对，一阶段多挨 1 次。
- 层叠让找对子更难、更容易连错，模拟量不出来，要试玩看（切片第六版）。

## Edge Cases

- **如果一回的数据不合法**：按规则 6 拒绝；开发版报错，正式版从列表拿掉并写日志（避免整个游戏打不开）。
- **如果所有回目都不合法**：显示出错页“戏本出错，请稍后再来”，不进对局。
- **如果中间一回被拿掉**：前一回的“下一回”和缺省预告指向再下一个能加载的回目。
- **如果存档里有一个已不存在的回目 `id`**：由“进度、三星与存档”处理（读取时忽略，写回时保留）。
- **如果 `seed` 网址参数不是整数**：忽略，用随机的 `salt`。
- **如果 `ch` 网址参数指向未解锁的回目**：开发版允许直接进；正式版不读这个参数。
- **如果 `newEffect` 写的兵种不在 deck 里**：警告；水牌上不显示这条规则说明。
- **如果最后一回赢了**：预告显示“全书未完，下回分解”，结算卡没有“下一回”。
- **如果没写 `cols`**：按 6 列。正式版新回目都应写 5（规则 2）。
- **如果满盘模式的 `Σ deck` 正好等于 `rows × cols`**：不叠，和第五版以前一样（第二回）。
- **如果 `Σ deck` 是单数格数**：不会发生，每种兵都是偶数块，总数一定是偶数；`rows × cols` 是单数（例如 7 × 5 = 35）时，`Σ deck` 至少 36，会有 1 张压底。
- **如果 5 列压境写了 `startRows` 3 或 5**：`Σ deck` 要等于 15 或 25，是单数，必有一种兵是单数块，一定拒绝。5 列压境只能 `startRows` 4。
- **如果压境写了 `waveList`、`cols` 是 5**：每一波是 2 对兵加 1 个空格位，空格位写 `null` 或 `'jm'`。写成 5 块兵的那一项被拒绝；写了 2 个 `'jm'`（兵只剩 3 块）也被拒绝。
- **如果 6 列压境的 `waveList` 里有 `'jm'`**：6 列每波 3 对兵、没有空格位，写拒马就少了兵，拒绝。
- **如果压境盘上只剩拒马**：算盘空（“盘面与连通”规则 9：`isEmpty()` 为真），立刻下压下一波；最后一波后只剩拒马就判胜。
- **如果压境最下一排只有拒马时到点下压**：不破城，拒马推出盘面后移除；这一行也不累计 `dangerMs`（拒马不算底排有块）。
- **如果 `phase2.specials` 没写**：用吕布的三种 `[sweep, charge, roar]`。没有 `phase2` 时写不了 `specials`，也没有特技（第二、三回）。
- **如果 `specialNames` 没写某个特技**：用缺省显示名（画戟横扫、赤兔冲阵、虎啸、铁索连环）。
- **如果回目 `failHint` 只写了一种原因**：其他原因用 `texts.failHint` 的缺省句。
- **如果 `boss.hp` 没写**：第一段血 = 开局盘上的对数（含压底的牌）。
- **如果没写 `phase2`**：只有一段血，没有特技（教人的回目可以这样排）。
- **如果主将的蓄力兵不在 `deck` 里**：拒绝加载（规则 6）。
- **如果推荐阵容里有人的蓄力兵不在 `deck` 里**：只警告；填槽时跳过他，水牌上那个槽空着或由玩家补。例如第八回没有旗，刘备变灰（“选将与解锁”规则 11）。
- **如果马把盘上的弓全部冲散、黄忠还没蓄满**（第十回）：被效果清掉的弓不蓄力；增兵和暴怒补兵还会按 `pool` 带回弓，黄忠可以再蓄。失败卡给“先蓄黄忠，再消马”。
- **如果 `slow=1` 让步数超过 15**（例如 `steps` = 12 → 18）：照用，不再检查范围；`slow` 只给试玩兜底。

## Tuning Knobs

每一回的全部字段都是调参项。初值见规则 13：第五回的血量来自垂直切片第六版（`prototypes/hulao-vertical-slice/`，模拟脚本 `sim.mjs` 加三次试玩）；其余各回来自关卡设计的估算（2026-10-30），没有跑模拟。

| 名称 | 默认 | 安全范围 | 调高 | 调低 |
|---|---|---|---|---|
| rows（非压境） | 6–7 | 6–8 | 一回变长，格子可能要缩放 | 一回太短，没有展开空间 |
| `cols` | 5（正式版编排），缺省 6 | 5–6 | 6 列时棋子只有 52–53 px，中老年点着费劲 | — |

| 压境 `interval` | 12000（第一、六、八回都是；原 10000 / 8000 / 7000） | 6000–12000 | 压境变松 | 5 列 `r_need` 变大，中老年跟不上 |

## Acceptance Criteria

- **GIVEN** 正式版 10 回数据（规则 13）和 `starters = [guan_yu]`，**WHEN** 加载，**THEN** 0 个拒绝、0 个警告。
- **GIVEN** 一回的 deck 有一种兵是 3 块，**WHEN** 加载，**THEN** 拒绝这一回，开发版报错并指出回目 `id` 和兵种。
- **GIVEN** 敌将回目 `rows = 6`、`cols = 5`，**WHEN** `Σ deck` 分别是 28、30、44、60、62，**THEN** 28 拒绝（盘铺不满），30、44、60 照常加载（30 不叠，44 压 14 张，60 每格都压一张），62 拒绝（超过 `rows × cols × 2`）。
- **GIVEN** 一回 `cols = 7`，**WHEN** 加载，**THEN** 拒绝；**GIVEN** 不写 `cols`、`rows = 6`、`Σ deck = 36`，**THEN** 按 6 列照常加载。
- **GIVEN** 压境回目 `cols = 5`、`startRows = 4`、`Σ deck = 24`，**WHEN** 加载，**THEN** 拒绝（压境要正好 `startRows × cols` = 20）。
- **GIVEN** 一回 `slots = 2`、`recommend = [guan_yu, zhao_yun]`、`lead = zhao_yun`，**WHEN** 加载，**THEN** 拒绝（第一位不是主将），开发版指出字段 `recommend`；`recommend` 只写一位时同样拒绝。
- **GIVEN** 一回 `lead = zhang_fei`、`deck` 里没有鼓，**WHEN** 加载，**THEN** 拒绝，开发版指出字段 `lead`；**GIVEN** 推荐阵容里的赵云没有盾，**THEN** 只警告。
- **GIVEN** 一回不写 `need`，阵容是黄忠、诸葛亮、刘备，**WHEN** 开局，**THEN** 三人的 `need` 分别是 3、4、3。
- **GIVEN** 压境回目 `rows = 7`，**WHEN** 加载，**THEN** 拒绝。
- **GIVEN** 压境回目 `interval = 3000`，**WHEN** 加载，**THEN** 拒绝；`interval = 5000`（合法但低于安全范围 6000），**THEN** 照常加载并警告。
- **GIVEN** 敌将回目的 `boss.enemy` 不在 `enemies` 表里，**WHEN** 加载，**THEN** 拒绝。
- **GIVEN** 两个回目 `id` 相同，**WHEN** 加载，**THEN** 拒绝第二个。
- **GIVEN** 推荐阵容里一位武将的蓄力兵只有 2 块、`need = 2`，**WHEN** 加载，**THEN** 只警告，照常加载。
- **GIVEN** `stars` 写成 `{t3: 9000, t2: 2000}`（3 星比 2 星宽松），**WHEN** 正式版加载，**THEN** 照常加载，评星用缺省阈值，日志里有记录。
- **GIVEN** ch02 被拒绝，**WHEN** 赢下 ch01，**THEN** 预告是“下回：赵子龙磐河大战”，“下一回”进入 ch03。
