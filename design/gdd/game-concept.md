# Game Concept: 三国连连看

*2026-10-30 用户改名：游戏显示名由“评书连连看·三国”改为“三国连连看”。*

*Created: 2026-10-26*
*Revised: 2026-10-26（原型迭代后改版，依据 `prototypes/index.md` 中 #2–#7 的试玩结论）*
*Status: Draft*

> 由 `/brainstorm`（`workflow: standard`）写成，经 7 版原型迭代后改版。第一版的钩子“盘内评书台词”被试玩推翻（“还是连连看，有点无聊”）。现在的核心是：**兵种效果 + 看得见的战场压力 + 盘下武将技能**。前身是 minimal 档的一页纸简报 `design/game-brief.md`，按模板保留不动。

## Elevator Pitch

> 这是一款竖屏三国连连看。**兵是消的，将是用的**：消兵给关张赵诸葛蓄力，顶住敌军压境、粮草断绝、敌将反击，一回一回把三国打完。
>
> 10 秒测试：会玩连连看的人一看就知道要消什么。多出来的只有两样：盘面上有东西在逼你，盘下有武将等你点。

| Aspect | Detail |

## Core Fantasy

你是坐镇一场三国战役的主帅。敌军压上来、粮草见底、敌将蓄力要出手，你一边快手消兵，一边盘算什么时候把关羽派出去斩开一排。技能放出的那一刻，台下一声好：“燕人张翼德在此！”

---

## Unique Hook

**像连连看，而且盘面上有看得见的压力，手里有武将技能：消兵是在给武将蓄力，什么时候放技能，决定这一仗守不守得住。**

- 一句话能讲清
- 改变的是玩法，不只是外观（第一版的教训，见 `prototypes/pingshu-sanguo-concept/REPORT.md`）
- 连着核心幻想：主帅调兵遣将
- 有原型证据：压力版“挑战上来了”，武将版“用技能的感觉对味了”。**试玩者只有开发者本人**，目标人群（中老年、摸鱼上班族）还没有试过

## Player Experience Analysis (MDA Framework)

### Target Aesthetics (What the player FEELS)

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Challenge** (obstacle course, mastery) | 1 | 三种战场压力：敌军压境、粮草有限、敌将反击；输赢由操作和判断决定 |
| **Fantasy** (make-believe, role-playing) | 2 | 主帅调用关张赵诸葛；技能放出时武将亲口喊台词 |
| **Sensation** (sensory pleasure) | 3 | 连斩、兵种效果一清一大片、技能清屏、泼墨亮相、盖章落定；脸谱和毛笔字。不震屏（美术圣经第 7 节） |
| **Narrative** (drama, story arc) | 4 | 故事决定每一回打什么仗、谁当主将（其余出阵武将由玩家点将）；回目标题与下回预告 |
| **Discovery** (exploration, secrets) | 5 | 新武将、新兵种效果按名场面登场（火烧博望坡、水淹七军） |
| **Submission** (relaxation, comfort zone) | 6 | 一紧一松的编排：难的一回后接一回爽快局 |
| **Fellowship** | N/A | 无联网；只有截图分享 |
| **Expression** | N/A | 不做 |

### Key Dynamics (Emergent player behaviors)

- 玩家会**为了蓄力去找某种兵**（想放关羽就先找刀）
- 玩家会**留着技能等时机**（压境时等最下面那排快压到红区，再放关羽）
- 玩家会**先打最危险的地方**（压境时优先消最靠近红区的块；粮草局先放火、不手动消营帐）
- 玩家会**用连斩逼退敌将**，一口气不连错（三连斩起每次让敌将退 1 步）

### Core Mechanics (Systems we build)

1. **连通消除**：点选两块，最多拐两个弯（可绕外圈）就消除；死局自动洗牌；连斩（连着消对、中间不连错，不再看时间）
2. **兵种效果**：火 → 所有营帐，马 → 所有弓兵，水 → 所有城寨；被清的那类块总是偶数个，保证盘面还能消完
3. **战场压力**（每回一种）：敌军压境、粮草有限、敌将反击
4. **武将技能栏**：消对应的兵给武将蓄力，满了点头像放技能（关羽过关斩将、张飞当阳一吼、赵云七进七出、诸葛亮神机妙算）
5. **回目编排**：故事决定每一回的压力类型、主将、新登场的兵种效果
6. **选将与解锁**（竖切片起）：每回开讲前，主将之外的技能槽由玩家从已解锁的武将里点将；武将随故事解锁（design/gdd/general-loadout.md）

## Player Motivation Profile

### Primary Psychological Needs Served

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** | 什么时候放技能、先打哪里、先放火还是先消别的，都是玩家的决定 | Core |
| **Competence** | 守住压境、省下粮草、打断敌将；三星、用时、最高连斩看得见进步 | Core |
| **Relatedness** | 三国是共同记忆；“我用一吼救回了长坂坡”可以拿去和家人聊、截图发小红书 | Supporting |

### Player Type Appeal (Bartle Taxonomy)

- [x] **Achievers**：每回三星、解锁武将、全书讲完
- [x] **Explorers**：下一回打什么仗、下一位武将和兵种效果是什么
- [ ] **Socializers**：不做联网社交
- [ ] **Killers/Competitors**：不做排行榜和 PvP

### Flow State Design

- **Onboarding curve**：一回只教一样新东西。头几回是“敌将反击、蓄力慢、一位武将”，之后逐回加入压境、粮草、更多武将和兵种效果
- **Difficulty scaling**：压境间隔、敌将蓄力、粮草余量逐回收紧（初值见 MVP Definition）；后期一回混用两种压力
- **Feedback clarity**：压境有警戒区、城垛线和倒计时条，粮草有数字和粮袋格，敌将有血量和蓄力条；技能蓄满时武将牌出现金框、抬起、冒出令牌、名字换成技能名，不发光（美术圣经第 3、7 节）
- **Recovery from failure**：输了叫“破城”“粮草断绝”“城破”，不扣任何东西，一键再来；需要提供“慢一点”的难度选项（见 Open Questions）

## Core Loop

### Moment-to-Moment (30 seconds)
找两块一样的连消；顺手留意盘下哪位武将快满了；压力逼近时，决定是先放技能还是继续手消。这个循环本身要爽：反馈即时，连斩、效果、技能各有一层“清一大片”的释放。

### Short-Term (5-15 minutes)
一回就是一场仗，1–3 分钟，用一种压力（敌军压境、粮草有限或敌将反击）。赢了出星级和下一回的标题预告。“再来一回”的冲动来自两处：差一点就守住了，或者想试试另一种放技能的时机。

### Session-Level (30-120 minutes)
**按 H5 改成一次摸鱼：3–10 分钟，2–4 回。** 每回结束是自然停点；下次回来的理由是下一回的标题、新武将即将登场、还没拿到三星的回目。

### Long-Term Progression
20 回主线，从桃园结义到三分天下。武将按故事固定加入（桃园：刘关张；长坂坡：赵云；三顾茅庐之后：诸葛亮……），兵种效果按名场面登场。全部讲完 =“全书讲完”，之后可以回头冲三星。

### Retention Hooks
- **Curiosity**：下一回的标题预告；下一位武将和兵种效果是什么
- **Investment**：已解锁的武将和三星（存在本地）
- **Social**：截图分享；三国是家人之间的共同话题
- **Mastery**：每回三星、最快用时、最高连斩（MVP 只存星级；用时和最高连斩只在结算卡上显示本回的，不存最好记录）

## Game Pillars

### Pillar 1: 一回一乐
每一回都要有释放的瞬间：连斩、兵种效果、技能清屏，一回里至少一次。

*Design test*：在“加规则”和“更爽快”之间，选更爽快。

### Pillar 2: 将在人为
武将是你手里的牌，不是盘上的块。放技能要是一个决定，也要是一个高潮。

*Design test*：一个新技能如果“蓄满就该马上放、没什么好想的”，就重新设计，直到“什么时候放”有讲究。

### Pillar 3: 故事决定这一回打什么仗
压力类型、主将、新登场的兵种效果，都由这一回的三国故事决定（守城、被追打压境，北伐打粮草，斗将打敌将反击）。其余的技能槽由你点将（用户决定，2026-10-30，见 `design/gdd/general-loadout.md`）。

*Design test*：编排一回时，先问“演义里这一仗难在哪”，再选压力，不反过来。

### Pillar 4: 一看就会
中老年第一次打开，不读说明就能玩：字大、块大，一回只教一样新东西。

*Design test*：新机制如果需要第二行说明，就砍掉、延后，或者拆成两回教。

### Pillar 5: 攒得踏实
所有奖励都是确定的：清哪一回就得哪位武将、哪个效果；星级只看“守得多稳”（敌将看丢了几颗心，压境看最下一排被压了多久，粮草看连不上的次数和余粮；用户决定，2026-10-27），用时和连斩只作记录，不评星。

*Design test*：在“惊喜掉落”和“确定奖励”之间，选确定。

> 支柱之间故意互相拉扯：“将在人为”要有讲究，“一看就会”要简单；Challenge 排第一，“一看就会”在给它设下限。

### Anti-Pillars (What This Game Is NOT)

- **NOT 抽卡、随机掉落、签到奖励**：破坏“攒得踏实”，并且有赌博感
- **NOT 武将等级、养成星级、装备这类养成数值**（每回结算的“三星评价”不算在内）：破坏“一看就会”，而且会把“将在人为”变成“数值碾压”
- **NOT 长过场、对话框**：故事只用回目标题、预告和技能台词来讲
- **NOT 血腥或恐怖画面**：受众是中老年，也不合作者的口味

## Visual Identity Anchor

> 由主会话起草：lean 模式跳过了美术总监评审（AD-CONCEPT-VISUAL），用户写入前看过。**已由 `/art-bible` 展开并修订，以 `design/art/art-bible.md` 为准**。修订包括：“脸谱”扩成“脸谱 + 行头”；台词底从半透明改为不透明度 ≥ 90%；技能就绪不再发光，改为金框、抬起、令牌、技能名四重提示；敌方和压力用墨青加锯齿。下面保留的是原始锚点。

**方向：戏台上的连连看**

**一句话规则**：一切看起来都像说书人桌上摆开的一场戏。

**支撑原则**：
1. **脸谱一眼认人**：武将（技能栏头像、敌将头像）用京剧脸谱，红关公、黑张飞、白曹操。*设计测试*：缩到 40 像素还能认出是谁，否则重画。
2. **字比图大**：台词和压力提示用大号毛笔风字体，压在半透明底上。*设计测试*：台词和图块抢视线时，字赢。
3. **纸面质感，不要金属光泽**：宣纸、木纹、印章。*设计测试*：在“写实立体”和“平面纸感”之间，选纸感。

**色彩哲学**：宣纸米黄做底，朱红代表我方和高潮（连斩、技能、效果），墨黑代表文字，描金只留给“技能可用”和三星。每种语义色都有形状备份（效果块的红框加角标、技能就绪时的金框和令牌；原稿写的是“发光边框”，已按美术圣经修改），不只靠颜色区分。

## Technical Considerations

| Consideration | Assessment |
| ---- | ---- |
| **Recommended Engine** | **不用引擎**：纯 HTML/CSS/JS，这是用户的硬约束。模板的选项只有 Godot、Unity、Unreal，均不适用（Godot 网页导出远超 2 MB）。7 版原型都是单文件 HTML，最大 34 KB |
| **Key Technical Challenges** | 低端安卓机流畅度；小红书内置浏览器里本地存档可能被清；中文毛笔字体不能整套内嵌（太大）；改变块分布的机制（斩一行、增兵、叠层）都要保证盘面还能消完（原型里已有做法） |
| **Art Style** | 2D 平面纸感，脸谱头像用 SVG |
| **Art Pipeline Complexity** | Medium（12 种兵种图标；6–8 位我方武将、约 10 位敌将的头像；约 15 个布景部件，外加每回 1 件标志物；见美术圣经第 5、6、8 节） |
| **Package Budget** | 整包不超过 2 MB（含代码、字体、图），离线，不用第三方库；预算分配见美术圣经第 8 节 |
| **Audio Needs** | Minimal（点击、碎裂、技能音效；MVP 不做） |
| **Networking** | None（离线） |
| **Content Volume** | 20 回 × 1 盘；每回 1 种压力；约 6–8 位我方武将；约 10 位敌将；一轮通关约 40–60 分钟 |
| **Procedural Systems** | 发牌随机，但保证有解（只影响盘面，不影响奖励）；压境的新兵正式版改为固定波次 |

## Risks and Open Questions

### Design Risks
- 压力对中老年可能太凶：开发者觉得“挑战上来了”，目标人群可能觉得被追着跑
- 四个技能的平衡：有的技能可能永远最优，“什么时候放”就失去了讲究
- 20 回的编排要做到“一回只教一样新东西”，同时三种压力轮换不腻

### Technical Risks
- 小红书内置浏览器可能清除 localStorage，武将解锁进度丢失
- 毛笔风字体的体积和授权

### Market Risks
- 小红书“小工具”的分发和曝光机制未知
- 三国消除类作品不少，要靠“连连看加压力加武将技能”这个组合立住

### Scope Risks
- 20 回编排加调参，是一个人几周里最容易被低估的工作量
- 脸谱美术约 20 张
- “约 6 周”是在美术圣经之前估的。美术圣经新增了约 18 个三档头像、布景部件库、毛笔体子集和构建检查等工作，而制作人的范围评审（PR-SCOPE）在 lean 模式下被跳过了，**需要重估**

### Open Questions
- 中老年能承受多大的压力？→ 找目标人群真人试玩武将版原型，比较默认参数和慢速档（原型里是 `?every=9000&charge=15000`；正式开发后是网址参数 `slow=1`，见回目编排规则 14）
- 要不要“慢一点”的难度选项？做成开关还是自动调节？→ 在系统设计阶段的难度曲线里定
- 存档丢失怎么办？→ 调研小红书 H5 的存储行为；兜底方案是可抄写的“进度码”

## MVP Definition

**Core hypothesis**：兵种效果、看得见的压力、盘下武将技能，三者合在一起，会让连连看变成“几分钟一场、有紧张有翻盘”的小仗，目标人群愿意一回接一回地打。

**Required for MVP**：
1. 连通消除、连斩、死局洗牌
2. 兵种效果（火、马、水）
3. 三种战场压力（敌军压境、粮草有限、敌将反击）
4. 四位武将的技能栏（关羽、张飞、赵云、诸葛亮）。**MVP 的例外**：四位武将每一回都在场，因为 MVP 要验证的是“压力加技能”；从竖切片起执行新的支柱 3（主将由故事定，其余槽由玩家点将，见 `design/gdd/general-loadout.md`；用户决定 2026-10-26 / 2026-10-30）
5. 3 回，每种压力一回：三英战吕布（敌将反击）、长坂坡（敌军压境）、六出祁山（粮草有限）
6. 本地存档（星级；MVP 三回一开始全开，没有解锁进度，用户决定 2026-10-27）

**Explicitly NOT in MVP**：
- 20 回全量编排
- 配音、音效、音乐
- 叠层、阵法这类盘面变体（作为以后编排的素材保留）
- 难度选项（先用网址参数调）
- 教学编排：MVP 一次就引入 3 种压力、4 位武将和 3 种效果，所以**检验不了支柱 4“一回只教一样新东西”**，这要等竖切片的编排来验证

**调参初值**（来自原型实测，进入系统设计文档的 Tuning Knobs）：
- 敌军压境：间隔 7/6/5 秒（原型三回的值；系统设计后改为 7 → 6.5 → 6，5 秒低于安全范围，见回目编排规则 11）
- 敌将反击：蓄力 10/9/8 秒；三连斩以上打断 25%（系统设计后加了上限：两次出手之间最多 50，用户决定 2026-10-27）；点错加 15%
- 粮草有限：余量 2
- 武将技能：蓄满要 2 对
- 连斩判定窗口：3 秒
