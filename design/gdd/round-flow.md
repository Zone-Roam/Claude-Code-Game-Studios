# 对局流程与时钟

> **Status**: Revised（2026-10-30，并入切片第四至六版和选将；待重新审查）
> **Author**: 用户 + 主会话（lean 模式）
> **Last Updated**: 2026-10-30
> **Last Verified**: 2026-10-27
> **Implements Pillar**: 1 一回一乐、4 一看就会

## Summary

一回仗从“开讲”（含点将）到“结算”的状态机，加上全局唯一的游戏时钟。时钟只在“对局中、没有任何令牌”时走；效果结算、技能亮相、敌将出手、敌将暴怒、洗牌、切后台、暂停都会让它停下，同时锁住盘面。敌将的压力按玩家的步数走，不按时间走，但出手仍在每帧的 `tick` 里结算。本系统还规定一次操作里各系统按什么顺序结算、什么时候检查胜负，并在一回结束时交出结果对象。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `盘面与连通、战场压力、回目编排与难度`

## Overview

对局流程是一回仗的骨架：开讲水牌（含点将）→ 对局 → 胜或败 → 结算卡 → 下一回或再来一回。它持有“游戏时钟”，所有带时间的规则（压境间隔、连斩推迟）都读这只表，不读真实时间，因此演出占用的时间永远不算进玩家的压力里。敌将模式的蓄力改为按步数（切片第五版，用户 2026-10-28 批准，见“战场压力”规则 22）：时钟仍然决定**什么时候结算**出手（`tick`），但不再决定**要不要**出手；连斩也改成“连着消、中间不连错”，计法归“清除效果与连斩”。它还管理“盘锁”：凡是盖住盘面的东西出现时，盘就锁住；东西撤掉，盘才放开（美术圣经第 7 节 R1）。多个系统都会对同一次点击作出反应，**谁先谁后只在本文规定一次**（规则 6），胜负也只在本文规定的“结算点”检查，所以“最后一刀”和“粮草归零”“火烧清屏”之间不会出现竞态。玩家感觉不到这个系统本身，但能感觉到它的结果：压力不会趁演出偷走时间，切出去接个电话回来局面还在。

## Player Fantasy

“该我的时间一秒不少。”台词、亮相、敌将出手都不算玩家的时间；切出去回个消息，回来时局面原封不动，点“接着讲”接着打。

## Detailed Design

### Core Rules

1. **一回的状态**：`开讲` → `对局` → `结束（胜/败）` → `结算`。“后台”和“暂停”是对局中的叠加情况，用令牌表达（规则 4）。
2. **开讲**：
   - 显示水牌，内容来自回目数据（回目、压力规则一句话、首次登场的效果）。时钟不走，盘锁住。
   - **点将**（选将与解锁，design/gdd/general-loadout.md 规则 9–14）：水牌下面是一排技能槽（最多 3 个），开局已按“上次阵容 → 推荐阵容 → 空着”填好。点非主将的槽展开可选武将，点一位换上，点“×”清空；可选武将不多于槽数时只显示、不展开。槽、可选武将牌、“×”都是覆盖卡上的按钮：不受盘锁影响，只受规则 9 的防连点约束（从水牌按钮出现时算起，展开的可选武将不另算）。
   - “开讲”按钮出现 `CARD_GUARD_MS` 后才接受点击（规则 9）。展开着可选武将时点“开讲”：收起展开，按槽里现有的武将开讲。
   - 点“开讲”的那一刻，槽里的武将按槽位顺序定为这一回的**出阵武将**（`loadout`），交给武将技能建武将牌；之后这一回里不能换将。空槽不影响开讲。
   - 点“开讲”后遮罩用 150 ms 撤掉，**撤完那一刻**才进入“对局”、时钟开始走（R1：遮挡与锁定同生同灭）。
3. **游戏时钟**：
   - 内部值 `gameTime`（毫秒，浮点），每个渲染帧推进一次，推进量见公式 dt_game。
   - 只有在“对局”状态、且令牌集合为空时才推进。
   - 单帧推进量在 0 到 `MAX_STEP_MS` 之间（负数按 0 算）。
   - **隐式后台**：对局中某一帧的 `dtReal` 超过 `BG_GAP_MS`（默认 1000 ms），视为页面刚从后台回来但没收到可见性事件：这一帧不推进，按规则 10 进入后台处理。
4. **令牌**：任何会盖住盘面或要停钟的东西都申请一个带原因的令牌，用完归还。完整清单：

   | 原因 | 谁申请 | 停钟 | 锁盘 | 时长 | 超时豁免 |
   |---|---|---|---|---|---|
   | `effect` | 清除效果与连斩 | 是 | 是 | `EFFECT_HIGHLIGHT_MS`（380） | 否 |
   | `skill` | 武将技能 | 是 | 是 | `SKILL_SHOW_MS`（950） | 否 |
   | `hostAttack` | 战场压力（普通出手、特技、被挡、被破） | 是 | 是 | `HOST_ATTACK_MS`（600） | 否 |
   | `phase` | 战场压力（敌将暴怒，换二阶段） | 是 | 是 | `PHASE_SHOW_MS`（1400） | 否 |
   | `reshuffle` | 本系统（代盘面：`ensurePlayable()` 先改好数据、返回 `reshuffle`，本系统据此申请） | 是 | 是 | `RESHUFFLE_SHOW_MS`（400） | 否 |
   | `background` | 本系统（可见性） | 是 | 是 | 直到点“接着讲” | 是 |
   | `pause` | 本系统（界面上报暂停印、横屏、返回键） | 是 | 是 | 直到点“接着讲” | 是 |
   | `tutorial` | 教学引导（竖切片） | 是 | 是 | 直到点继续 | 是 |

   - 有时长的令牌（前五种）按**前台真实时间**计时：只累计页面可见、且没有 `background`、`pause` 令牌的时间。切后台、点暂停、转横屏时它们的计时都暂停，点了“接着讲”才继续走完剩下的部分。所以演出不会在暂停卡下面偷偷播完。
   - `background` 和 `pause` 各自最多一个：重复申请返回同一个令牌。
   - 有时长的令牌到点时，由本系统通知持有者“演出结束”，持有者完成它的效果（例如技能落到盘面）后归还。持有者改盘面得到的结果（`clear` 等）交回本系统分发（规则 6 的分发表）。
   - 有时长的令牌持有超过 `TOKEN_MAX_MS`（前台时间）时**强制归还**：移出令牌集合；持有者还没收到过“演出结束”就补发一次，已经收到过的不再重发（效果只完成一次）；开发版报警告。
   - 令牌计时用的 `dtReal` 与时钟一样处理：负数按 0；超过 `BG_GAP_MS` 的那一帧不计（视为刚从后台回来，见规则 3）。
   - 没有其他种类的令牌。喊字位上的字（“最后一波”等）、盘上的连斩字、关羽的“选排”（规则 5a）都不申请令牌，不停钟、不锁盘（界面规则 R2）。
5. **盘锁**：盘锁住 ⇔ 状态不是“对局”，或令牌集合不为空。盘锁住时，落在盘上和武将牌上的点击直接丢弃，不缓存。覆盖卡上的按钮不受盘锁影响，只受规则 9 的防连点约束。
5a. **关羽选排时的输入路由**（用户决定，2026-10-30；技能本身见“武将技能”）：
   - **进入**：关羽就绪、盘没锁时点关羽牌，不放技能，而是进入“选排”：清掉盘上当前的选中，各行高亮。不消耗蓄力，不申请令牌，不算一步（敌将只按步走，所以选排时敌将不动）。
   - **选排期间点盘**：点到可选的行（哪些行可选由“武将技能”定，例如有兵或有拒马的行）的任意一格 = 选这一排，不当作选中块，不交给盘面的 `tap`。这时才放技能：关羽的蓄力清零，申请 `skill` 令牌，退出选排。点到不可选的行：没有反应，仍在选排。
   - **取消**：选排期间再点关羽牌、点其他武将牌、或点盘外任何地方（台眉、桌沿空白处），都退出选排，不消耗蓄力，那一下点击不做别的事（点其他武将牌不会放他的技能）。暂停印仍按规则 11 处理，不算取消。
   - **被打断**：选排期间盘锁住（例如申请到 `pause`、`background` 令牌），选排保留，回来后接着选；压境下压了一排时选排取消（行号变了），关羽回到就绪；本回结束（例如压境到点破城）或点“回书目”时，选排直接作废，不消耗蓄力。
   - 选排是盘上的一种输入模式，归本系统路由，不是令牌：压境模式里时钟照走、到点照样下压（下压后选排取消，见上）。
   - **黄忠选列**（用户决定，2026-10-30；技能见“武将技能”规则 14b）：路由同上，“排”换成“列”。唯一不同：压境下压时**不取消**选列（列号不变），高亮按新盘面重画。关羽选排和黄忠选列互斥：一个在进行时点另一位的牌 = 取消。
6. **结算顺序与分发**：
   1. 每帧先处理这一帧到达的点击，再推进令牌计时和时钟（`tick`），完整顺序见第 7 条。
   2. 盘面处理点击，返回 `match` / `miss` / 只改选中（见“盘面与连通”规则 7）。
   3. 收到 `match` 或 `miss` 时，本系统按固定顺序同步通知：
      ① 清除效果与连斩 `onMatch(match)`（连斩计数和连斩奖励、判断是否触发兵种效果）；
      ② 武将技能 `onMatch(match)`（蓄力）；
      ③ 战场压力 `onMatch(match)` / `onMiss(miss)`（扣粮、敌将伤害、敌将走步：连上 1 步、连错 2 步）。因为 ① 在 ③ 前面，打出三连斩的那一对对敌将是“先退 1 步、再走 1 步”。走满的出手**不在这里**发生，留到本帧的 `tick`；
      ④ 界面与交互（画连线、抽走或晃动；这时连斩数已经更新，连线该不该变朱已经确定）。
   4. 其他结果的来源和去向（分发表）：

      | 结果 | 产生于 | 何时改盘面或压力 | 演出 | 本系统转给 |
      |---|---|---|---|---|
      | 效果的 `clear` | 清除效果在 `effect` 令牌到点时调用 `clearKind` | 令牌到点后 | 先演出（高亮 380 ms），后清除 | 战场压力 `onClear`，然后界面 |
      | 技能的 `clear` | 武将技能在 `skill` 令牌到点时调用 `clearCells`/`clearKind` | 令牌到点后 | 先演出（亮相 950 ms），后生效 | 战场压力 `onClear`，然后界面（画朱勾残影） |
      | 张飞、赵云、诸葛亮对压力的效果（吓退、加粮、退步震慑、护盾、破特技） | 武将技能在 `skill` 令牌到点时调用压力的接口 | 令牌到点后 | 同上 | — |
      | 关羽斩一排的 `clear` | 选排后（规则 5a）武将技能在 `skill` 令牌到点时调用盘面 | 令牌到点后 | 同上 | 战场压力 `onClear`，然后界面 |
      | `push` | 战场压力在 `tick` 里调用 `pushRowFromTop` | **当场** | 盘整体下移 240 ms，不申请令牌、不锁盘（推行宽限见“界面与交互”规则 17） | 不经本系统：战场压力直接发 `push` 事件给界面 |
      | 敌将出手（普通：扣心、`add`；特技：横扫、拒马、虎啸；被挡；被破） | 战场压力在 `tick` 里，条件是步数走满且 `hp > 0` | **当场** | 之后申请 `hostAttack` 600 ms | 不经本系统：战场压力直接发 `hostAttack` 事件给界面 |
      | 敌将暴怒（补满援军、换血换步数） | 战场压力在 `tick` 里，条件是一阶段打空或盘面清空 | **当场** | 之后申请 `phase` 1400 ms | 不经本系统：战场压力直接发 `bossPhase` 事件给界面 |
      | `reshuffle` | 盘面 `ensurePlayable()` | **当场** | 之后本系统申请 `reshuffle` 400 ms | 界面 |
      | 保底失败的 `clear`（`source: 'reshuffle'`，理论上不发生） | 盘面 `ensurePlayable()` | **当场** | 无 | 战场压力 `onClear`，然后界面 |

      压力自己调用的 `addPairs`、`pushRowFromTop`、`shuffleTopRows`、`placeBlocks` 的结果由压力直接拿到，不再转回压力。
   5. **结算点**：令牌集合里没有任何令牌（计时令牌、`background`、`pause` 都没有），且自上一个结算点以来发生过点击结果、令牌到点、`tick` 里的下压、出手和换阶段、或盘面的保底清除时，在以下两个时刻各做一次：每处理完一次点击（第 7 条第 ② 步）；本帧令牌计时和 `tick` 之后（第 7 条第 ⑤ 步）。在结算点依次做：
      - 先检查胜负（规则 7）；已分出胜负就进入“结束”，不再洗牌。
      - 没分出胜负时，调用盘面的 `ensurePlayable()`。如果它洗了牌，申请 `reshuffle` 令牌，令牌结束后再到下一个结算点。
   6. 只有 `dtGame > 0` 时才调用 `tick`；`tick` 之后如果没有令牌，也是一个结算点（压境到点破城、粮草和敌将的状态都在这里检查）。这一帧的 `tick` 里没有下压、出手、换阶段时，盘面没变，结算点只判胜负、不必调用 `ensurePlayable()`。敌将的 `tick` 不用 `dtGame` 的大小，只用它判断“这一帧时钟走了”：步数在点击时（第 ② 步）就走了，走满的出手在同一帧第 ④ 步发生；第 ② 步里如果申请了令牌（例如这一对触发了效果），出手就等令牌归还后的第一次 `tick`。
   7. **一帧内的顺序**：① 隐式后台判断（规则 3：`dtReal > BG_GAP_MS` 就进入后台处理，本帧到此为止）；② 按到达顺序处理本帧落在盘上、武将牌上和盘外的点击（暂停印、覆盖卡按钮不受盘锁影响，按规则 9、11 处理；选排期间按规则 5a 路由）：状态已不是“对局”，或**本帧开始时或此刻**的令牌集合有一个不为空，这次点击就丢弃（所以演出最后一帧到达的点击、同一帧里排在一次放技能或触发效果之后的点击，都会被丢弃，之后也不补执行）；每处理完一次点击、令牌集合仍为空时，就地做一次结算点（第 5 条）：分出胜负就进入“结束”，本帧后面的点击因为状态改变而丢弃；洗了牌就申请 `reshuffle` 令牌，后面的点击因为“此刻”有令牌而丢弃；③ 用本帧 `dtReal` 推进有时长令牌的计时，到点的通知持有者（持有者完成效果、归还令牌、交回结果）；在第 ② 步新申请的令牌从下一帧开始计时；④ 这时令牌集合为空才算 `dtGame > 0`，调用 `tick`；⑤ 到结算点就按第 5 条处理。
7. **胜负检查**：
   - 本系统只在结算点（规则 6.5、6.6）调用战场压力的 `outcome()`，得到 `{result: 'win' | 'lose' | null, reason}`。
   - 战场压力不主动通知胜负，只回答查询。所以“胜利优先”只需要一条规则：同一次检查里先看胜利条件，再看失败条件（战场压力的 `outcome()` 按这个顺序实现）。
   - 有任何令牌时不检查。所以效果清空盘面、技能清空盘面、敌将打掉最后一颗心，都会等演出播完再判（美术圣经 R5：心先在原位变成虚线）；暂停卡、接着讲卡在的时候也绝不会判出胜负。
   - 敌将有两段血时，一阶段打空不算胜：`outcome()` 返回 `null`，本帧 `tick` 里换阶段（暴怒），`phase` 演出播完后的结算点照常检查。先看血再出手：每次点击后的结算点先于 `tick`，所以打空血的那一刀不会再引出一次出手。
8. **结束与结果对象**：
   - 检查出胜负时进入“结束”：停钟，锁盘，并**立刻**调用进度的 `settle(RoundResult)`，拿回 `SettleOutcome`（星级、原因一句等；胜利卡盖章时星级已经定了）。
   - 进入“结束”时不会有任何令牌（规则 7 保证）；开发版对此做断言。
   - 结果对象（本系统定义，字段固定）：

     ```
     RoundResult {
       chapterId: string        // 回目 id
       mode: 'press' | 'food' | 'boss'
       win: boolean
       reason: null | '破城' | '粮草断绝' | '城破'   // 赢时为 null
       gameTimeMs: int          // 结束时的 gameTime，向下取整
       maxCombo: int            // 来自清除效果与连斩
       loadout: string[]        // 实际出阵武将 id，按槽位顺序，0–3 个；进度据此写本回的 loadout（选将与解锁规则 13）
       skillsUsed: { [generalId]: int }  // 只含出阵武将，各自释放次数，来自武将技能
       bossPhase: null | 1 | 2  // 敌将模式结束时所在的阶段（hud().phase）；其他模式为 null。只做记录和失败提示，不参与评星
       metrics: { dangerMs: int }                 // press
              | { foodLeft: int, misses: int }    // food
              | { heartsLost: int }               // boss
     }
     ```
   - 界面播完收尾演出后调用 `endingDone()`，本系统进入“结算”。收尾演出：胜利 `ENDING_WIN_MS`（2000 ms，切片第四版“击碎结局”：剩余兵块炸飞、敌将头像碎裂、闪白，1500 ms 时胜利卡进场盖章）；失败 `ENDING_LOSE_MS`（300 ms）。
9. **覆盖卡与防连点**：开讲水牌、胜利卡、失败卡、接着讲卡、暂停卡、横屏卡上的按钮，在**按钮出现后** `CARD_GUARD_MS` 内不接受点击。胜利卡的按钮在收尾演出（`ENDING_WIN_MS`）结束、盖章落定后才出现，所以从按钮出现时开始算。水牌上的技能槽和可选武将牌也算水牌上的按钮。
10. **后台**：
    - 只在“对局”状态处理后台。页面变为隐藏（`visibilitychange` 变 hidden 或 `pagehide`），或出现隐式后台（规则 3），就申请 `background` 令牌。
    - 回到前台时，界面显示“接着讲”卡；点按钮后归还 `background` 令牌。
    - 在开讲、结束、结算状态切后台：不申请令牌，不显示卡片，回来时状态不变（这些状态里时钟本来就不走）。
11. **暂停**：
    - 三种模式的台眉都有暂停印（粮草模式不限时，暂停印主要用来“回书目”；美术圣经只要求限时模式有，这里为了给粮草模式留一个出口而扩大）。对局中随时可以点，**盘锁住时也可以**（它不在盘上）。界面把点击上报给本系统，由本系统申请 `pause` 令牌并显示暂停卡（“接着讲”主按钮、“回书目”次按钮）。
    - 对局中手机转成横屏，同样申请 `pause` 令牌，显示横屏卡“请竖着拿手机”（没有按钮）；转回竖屏后横屏卡换成暂停卡。横屏和后台同时发生时，回到前台后先显示横屏卡，转回竖屏后显示暂停卡。
    - “接着讲”归还 `pause` 令牌；同时持有 `background` 时一并归还（页面此时一定可见、竖屏）。暂停卡开着时切到后台，回来后仍显示暂停卡（两个按钮都在），不另出接着讲卡。
    - “回书目”放弃这一回：清空全部令牌、**不通知**任何持有者（演出不再完成），不交结果对象，不写存档，回到书目。
12. **种子与重来**：
    - 每一回开局时，`seed = hash32(chapterId, attempt, salt)`，交给盘面。
    - `attempt`：这一页面会话里这一回目第几次开局，从 1 开始；“再来一回”或从书目重新进入都加 1。不存档。
    - `salt`：页面加载时随机生成的 32 位整数。开发版和 MVP 测试包读取网址参数 `seed=N`，把 `salt` 固定为 N，此时“同一回目、同一 attempt”一定得到同一张盘；正式发布包不读这个参数。
13. **结算后的去向**：
    - 胜利卡：有下一回时为“下一回”（主）、“再来一回”、“书目”；最后一回（没有下一回）时为“再来一回”（主）、“书目”。
    - 失败卡：“再来一回”（主）、“书目”。
    - “下一回”是回目数据里顺序上的下一个**能加载**的回目（见“回目编排与难度”）。
    - “再来一回”回到同一回的水牌，槽位沿用刚才的出阵阵容，可以再换（选将与解锁规则 14）；“下一回”回到下一回的水牌，槽位按那一回的规则 9 填。

### States and Transitions

| 状态 | 时钟 | 盘 | 进入 | 离开 |
|---|---|---|---|---|
| 开讲（含点将） | 停 | 锁（水牌按钮、技能槽可点） | 从书目选回目；“再来一回”；“下一回” | 点“开讲”定下出阵武将，遮罩撤完 → 对局；点“回书目” → 书目 |
| 对局 | 走（无令牌时） | 开（无令牌时） | 开讲结束 | `outcome()` 给出胜或负 → 结束；“回书目” → 书目 |
| 对局 · 选排（叠加） | 照走（不是令牌） | 开，点盘 = 选排 | 关羽就绪时点关羽牌 | 选了一排 → 放技能（`skill` 令牌）；再点关羽牌、点别的武将牌或盘外 → 取消；本回结束 → 作废 |
| 结束（胜/败） | 停 | 锁 | 见上 | 收尾演出完成 → 结算 |
| 结算 | 停 | 锁（只开卡片按钮） | 结束演出完成 | 下一回 / 再来一回 → 开讲；书目 → 书目 |

接口签名（实现时的名字以技术决策记录为准）：`acquire(reason, durationMs?, onEnd?) → token`、`release(token)`（重复归还无副作用）、`dispatch(result)`（持有者把改盘面得到的结果交回本系统）；本系统调用 `effects.onMatch`、`skills.onMatch`、`pressure.onMatch`、`pressure.onMiss`、`pressure.onClear`、`pressure.tick(dtGame)`、`pressure.outcome() → {result, reason}`、`pressure.metrics()`、`pressure.hud()`、`board.ensurePlayable()`、`skills.tapCard(id)`、`skills.rowSelectable(row) → bool`、`skills.cutRow(row)`、`progress.settle(RoundResult) → SettleOutcome`。（`rowSelectable`、`cutRow` 是给关羽选排的接口，名字以“武将技能”和技术决策记录为准。）

**循环依赖的解法**：压力系统不调用流程，只回答 `outcome()` 查询；界面只通过令牌影响时钟。

## Formulas

The dt_game formula is defined as:

`dtGame = running ? clamp(dtReal, 0, MAX_STEP_MS) : 0`，其中 `running = (state == 对局) AND (tokens == ∅) AND (dtReal ≤ BG_GAP_MS)`

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| dtReal | float | 任意 ms（负数按 0） | calculated | 两帧之间的真实时间 |
| MAX_STEP_MS | int | 50–500 | data file | 单帧推进上限，默认 250 |
| BG_GAP_MS | int | 600–3000 | data file | 超过就当作刚从后台回来，默认 1000；必须大于 MAX_STEP_MS |
| tokens | set | — | calculated | 当前未归还的令牌 |

**Output Range:** 0 到 MAX_STEP_MS。
**Example:** 60 fps 下 dtReal ≈ 16.7 → dtGame ≈ 16.7；技能演出期间 dtGame = 0；卡顿 600 ms 的一帧 → dtGame = 250；一帧 dtReal = 4000 → dtGame = 0，并进入后台处理。

The token_clock formula is defined as:

`elapsed(token) = Σ 前台帧的 clamp(dtReal, 0, ∞)`（页面可见、没有 `background`、`pause` 令牌，且 `dtReal ≤ BG_GAP_MS` 的帧）；`elapsed ≥ duration` 时到点；`elapsed ≥ TOKEN_MAX_MS` 时强制归还

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| duration | int | 200–1500 ms | 各系统 | 见规则 4 的表（下限对应清除效果 EFFECT_HIGHLIGHT_MS 的安全范围） |
| TOKEN_MAX_MS | int | 2000–10000 | data file | 有时长令牌的最长持有时间，默认 5000 |

**Output Range:** 有时长的令牌一定会在 TOKEN_MAX_MS 的前台时间内离开令牌集合。
**Example:** 效果高亮进行到 200 ms 时切后台 10 分钟（或点了暂停），回来点“接着讲”，再过 180 ms 到点。

The card_guard formula is defined as:

`accept(cardTap) = (now − buttonShownAt ≥ CARD_GUARD_MS)`；`accept(boardTap) = NOT boardLocked`

**Variables:**
| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| CARD_GUARD_MS | int | 200–1000 | data file | 按钮出现后不响应点击的时长，默认 500（UX） |
| buttonShownAt | float | — | calculated | 这张卡的按钮出现的时刻（真实时间） |

**Output Range:** true / false。
**Example:** 失败卡在 t = 1000 ms 出现（按钮同时出现），t = 1300 的点击无效，t = 1600 有效；胜利结局从 t = 0 开始，t = 1500 胜利卡进场，t = 2000（`ENDING_WIN_MS`）收尾完成、按钮出现，t = 2300 无效、t = 2500 有效。

## Edge Cases

- **如果同一次检查里胜利条件和失败条件都成立**：判胜（`outcome()` 先看胜利）。
- **如果效果或技能清空了盘面**：演出播完、令牌到点、效果落到盘面后，到达结算点才判胜；胜利盖章在朱勾残影消失之后开始。
- **如果敌将打掉最后一颗心**：`hostAttack` 演出 600 ms 播完（心变成虚线）后，到达结算点才判负。
- **如果玩家在敌将模式里长时间不动**：时钟照走，`tick` 照常调用，但步数不涨，敌将不出手。
- **如果一对消除同时触发了效果、又让敌将步数走满**：本帧申请了 `effect` 令牌，不调用 `tick`；效果演出结束、清除落到盘面后，先到结算点（血打空就判胜或换阶段），再在下一次 `tick` 出手。
- **如果一阶段打空和步数走满发生在同一下**：结算点 `outcome()` 返回 `null`；`tick` 里先换阶段，不出手；持有 `phase` 令牌 1400 ms，期间点击丢弃。
- **如果暴怒演出中切后台或点暂停**：`phase` 令牌计时暂停，回来点“接着讲”后走完剩下的部分。
- **如果关羽选排时压境到点下压**：照常下压，选排取消，关羽回到就绪（与“武将技能”规则 11 一致）；如果这一下破城，进入“结束”，选排作废，蓄力不扣（反正已经结束）。
- **如果关羽选排时点了暂停印**：申请 `pause`，选排保留；点“接着讲”后接着选。点“回书目”则选排作废。
- **如果关羽选排时同一帧先后到达“点一排”“点张飞牌”**：第一次点击放出关羽并申请 `skill` 令牌，第二次点击因为“此刻”有令牌被丢弃（规则 6.7 第 ② 步）。
- **如果水牌上展开着可选武将时切后台**：开讲状态不申请令牌，回来时展开状态不变。
- **如果玩家把副将槽都清空了再开讲**：照常开讲。主将槽不能清空，所以出阵武将至少 1 位。
- **如果某个有时长的令牌超过 TOKEN_MAX_MS 未归还**：强制归还（移出令牌集合）；持有者在整个过程中只收到一次“演出结束”（到点时已经收到过的，强制归还时不再发），开发版报警告。`background`、`pause`、`tutorial` 不受此限。
- **如果切后台或点暂停时正处在效果结算中**：`effect` 令牌的计时暂停；回来点“接着讲”后，效果把剩下的时间走完再落到盘面。暂停卡在的时候不会到结算点，也不会判出胜负。
- **如果演出中点暂停、再点“回书目”**：清空全部令牌，演出不再完成，盘面和存档都不变。
- **如果切后台时间很长（几小时）**：时钟推进为 0（有 `background` 令牌）；回来后第一帧也受 MAX_STEP_MS 约束。
- **如果可见性事件没有送到**：靠隐式后台（规则 3）兜底：大间隔的那一帧不推进，并出“接着讲”卡。
- **如果反复切前后台**：`background` 最多一个，一次“接着讲”就能归还。
- **如果在开讲、结束、结算状态切后台**：不申请令牌、不出卡，回来时状态不变。
- **如果暂停卡和后台同时出现**：点“接着讲”同时归还两者。
- **如果玩家在“再来一回”上连点**：第一次点击进入开讲；水牌的按钮出现后 500 ms 内的点击无效。
- **如果盘面已空但胜利条件还没满足**（压境还有波次）：不判胜，由战场压力在下一次 `tick` 立刻推下一波。
- **如果最后一回赢了**：胜利卡没有“下一回”。
- **如果对局中点“回书目”**：这一回不算，不交结果对象，`attempt` 照常加 1。

## Dependencies

- **依赖（上游）**：盘面与连通（硬：点击结果、`ensurePlayable`、种子）、战场压力（硬：`tick`、`outcome`、`metrics`、`hud().phase`、`hostAttack` 和 `phase` 令牌）、回目编排与难度（数据：模式、水牌、下一回）、选将与解锁（design/gdd/general-loadout.md；硬：水牌上的点将、开讲时的出阵武将）。
- **被依赖（下游）**：清除效果与连斩（硬：游戏时钟、通知顺序、`effect` 令牌）、武将技能（硬：出阵武将、通知顺序、`skill` 令牌、盘锁、关羽选排的输入路由）、进度三星与存档（硬：结果对象，含 `loadout`）、界面与交互（硬：状态、令牌、覆盖卡、选排高亮、点将区）、教学引导（竖切片，硬：`tutorial` 令牌）。
- 和战场压力的循环依赖用“查询而不是事件”解开（见 Interactions）。
- **实现备注**（→ 技术决策记录）：状态机和时钟只做计算，不读写页面元素；可见性和横竖屏变化由界面层转成调用传进来，测试时可以直接喂假的 `dtReal`。

## Tuning Knobs

| 名称 | 默认 | 安全范围 | 调高 | 调低 | 相互影响 |
|---|---|---|---|---|---|
| MAX_STEP_MS | 250 | 50–500 | 卡顿后压力一下子推进太多 | 低帧率下压力走得比真实时间慢 | 必须小于 BG_GAP_MS |
| BG_GAP_MS | 1000 | 600–3000 | 后台兜底反应慢 | 偶发卡顿被误当成切后台 | 必须大于 MAX_STEP_MS |
| CARD_GUARD_MS | 500 | 200–1000 | 按钮显得迟钝 | 连点会误触下一张卡 | — |
| TOKEN_MAX_MS | 5000 | 2000–10000 | 漏还的令牌冻结太久 | 正常演出被提前打断 | 必须大于所有有时长令牌的 duration（最长是 `PHASE_SHOW_MS` 1400） |
| ENDING_WIN_MS | 2000 | 1100–2500 | 胜利后等太久才能点下一回 | 击碎演出播不完 | 切片第四版“击碎结局”从 1100 改为 2000；胜利卡 1500 ms 进场 |
| ENDING_LOSE_MS | 300 | 300 | — | — | 美术圣经：失败遮罩 300 ms 匀速渐入 |

`PHASE_SHOW_MS`（1400）归“战场压力”，这里只登记令牌。

## Visual/Audio Requirements

依据美术圣经第 2 节①⑧⑨、第 7 节：

- 开讲水牌：盘面压 55% 墨遮罩，水牌在最上层，下面是一排技能槽（主将槽盖“主将”朱印）；点“开讲”后遮罩 150 ms 渐出。点将区样式归“界面与交互”。
- 关羽选排：各行高亮，提示“点一排”；样式归“界面与交互”。
- 胜利（击碎结局，切片第四版，共 `ENDING_WIN_MS` 2000 ms）：剩下的兵块从中心往外按每波 4 块炸飞；敌将大头像弹出，650 ms 裂开并抖动，950 ms 碎成 10 片飞散，全屏纸色闪一下，手机震 80 ms；1500 ms 胜利卡进场（亮纸 90% 遮罩、深朱方印、三星逐颗盖章，节奏按美术圣经压缩）；2000 ms 按钮出现。碎片用静态切形，只动 transform 和 opacity，同时动的元素约 24 个。闪白和震动是否符合美术圣经第 7 节，待美术总监确认。
- 失败：台面色 70% 遮罩 300 ms 匀速渐入，虚线空印位；不震屏、不出红叉。
- 接着讲卡、暂停卡：55% 墨遮罩加按钮。
- 音效（完整版）：醒木（开讲）、盖章。

`art-director` 未单独咨询（lean 模式）；以上取自美术圣经。

## Game Feel

- 开讲是醒木“一拍”：点按钮后 150 ms 就能开始点块。
- 演出期间压力绝不前进；玩家应当感觉“台词和技能是白给的时间”。
- 结算卡按钮在盖章落定之后才出现，再加 500 ms 防护，避免最后几下连点误按“下一回”。

## UI Requirements

覆盖卡：开讲水牌、胜利卡、失败卡、接着讲卡、暂停卡、横屏卡；台眉左上角的暂停印（三种模式都有）。具体样式见“界面与交互”。

## Acceptance Criteria

- **GIVEN** 对局中且没有令牌，**WHEN** 喂入 60 帧、每帧 dtReal = 16.7，**THEN** `gameTime` 增加 1002 ± 1。
- **GIVEN** 对局中，**WHEN** 喂入一帧 dtReal = −5，**THEN** `gameTime` 不变。
- **GIVEN** 对局中，**WHEN** 喂入一帧 dtReal = 600，**THEN** `gameTime` 增加 250。
- **GIVEN** 对局中，**WHEN** 喂入一帧 dtReal = 4000，**THEN** `gameTime` 不变，持有 `background` 令牌，界面收到“显示接着讲卡”。
- **GIVEN** 持有 `effect` 令牌（380 ms），**WHEN** 喂入 30 帧前台帧（共 500 ms），**THEN** 令牌在第 23 帧到点、持有者收到“演出结束”；第 1–22 帧 `gameTime` 不变，第 23 帧起恢复推进。
- **GIVEN** 两个不同原因的令牌，**WHEN** 只归还其中一个，**THEN** 时钟仍然不走、盘仍然锁住。
- **GIVEN** 持有 `effect` 令牌，**WHEN** 玩家点块，**THEN** 点击被丢弃，令牌归还后不会补发。
- **GIVEN** 连续两次申请 `background`，**WHEN** 点一次“接着讲”，**THEN** 令牌集合为空。
- **GIVEN** 开讲状态，**WHEN** 页面隐藏后恢复，**THEN** 不申请令牌，不显示“接着讲”卡。
- **GIVEN** 一个持有者到点后迟迟不归还的 `effect` 令牌，**WHEN** 前台时间累计到 TOKEN_MAX_MS，**THEN** 令牌不在集合里，持有者在整个过程中只收到过一次“演出结束”（到点时那一次），开发版记录警告；`pause` 令牌持有 20 秒不会被强制归还。
- **GIVEN** 持有 `effect` 令牌、已走 200 ms，**WHEN** 点暂停印并在暂停卡上停 5 秒，**THEN** 这 5 秒里令牌没有到点、没有到结算点；点“接着讲”后再过 180 ms 前台时间到点。
- **GIVEN** 持有 `skill` 令牌，**WHEN** 点暂停印再点“回书目”，**THEN** 令牌集合清空，技能没有生效，`settle()` 没有被调用，存档不变。
- **GIVEN** 盘锁住（持有 `effect` 令牌），**WHEN** 点暂停印，**THEN** 申请到 `pause` 令牌并显示暂停卡。
- **GIVEN** 对局中，**WHEN** 手机转成横屏，**THEN** 持有 `pause` 令牌，显示横屏卡；**WHEN** 转回竖屏，**THEN** 显示暂停卡。
- **GIVEN** 开讲水牌出现，**WHEN** 按钮出现后 300 ms 点“开讲”，**THEN** 无反应；600 ms 时生效。
- **GIVEN** 持有 `effect` 令牌、还剩 10 ms，**WHEN** 这一帧（dtReal 16.7）同时到达一次点盘，**THEN** 点击被丢弃；令牌在这一帧到点，之后也不补执行。
- **GIVEN** 敌将模式、hp = 1、hearts = 1、出手演出进行中，**WHEN** 演出最后一帧玩家点了一对可连的块，**THEN** 点击被丢弃，结算点判“城破”。
- **GIVEN** 持有任何令牌，**WHEN** 一帧过去，**THEN** 没有调用 `tick`。
- **GIVEN** 粮草模式 food = 1、盘上还有几对，**WHEN** 卡顿的一帧里先到一次“连不上”、再到一次能清空盘面的消除，**THEN** 第一次点击后就地结算判“粮草断绝”，第二次点击被丢弃。
- **GIVEN** 第 0 帧玩家消掉一对火（申请 `effect` 令牌 380 ms），**WHEN** 之后每帧 16.7 ms，**THEN** 第 0 帧不计令牌时间，第 23 帧到点。
- **GIVEN** 演出中（持有 `skill` 令牌），**WHEN** 同一帧里点暂停印，**THEN** 申请到 `pause` 令牌（暂停印不受盘锁影响）。
- **GIVEN** 张飞、赵云都就绪、没有令牌，**WHEN** 同一帧里先后到达“点张飞”“点赵云”两次点击，**THEN** 只放出张飞，第二次点击被丢弃。
- **GIVEN** 关羽就绪、没有令牌，**WHEN** 点关羽牌，**THEN** 进入选排：没有申请任何令牌，关羽蓄力不变，`gameTime` 照走，敌将步数不变，盘上原来的选中被清掉。
- **GIVEN** 选排中，**WHEN** 点第 4 行（可选）里的一个空格，**THEN** 放出关羽：蓄力清零，持有 `skill` 令牌 950 ms，退出选排；盘面的 `tap` 没有被调用。
- **GIVEN** 选排中，**WHEN** 点一个不可选的行，**THEN** 没有反应，仍在选排。
- **GIVEN** 选排中，**WHEN** 再点关羽牌 / 点赵云牌（已就绪）/ 点台眉空白处，**THEN** 退出选排，关羽蓄力不变；点赵云牌那一次不放赵云。
- **GIVEN** 选排中，**WHEN** 点暂停印、再点“接着讲”，**THEN** 仍在选排。
- **GIVEN** 压境、选排中、最下一行有块，**WHEN** 到点下压，**THEN** 判“破城”进入“结束”，选排作废。
- **GIVEN** 敌将一阶段 steps 7 / 8、hp 5，**WHEN** 一帧里连上一对（没触发效果），**THEN** 同一帧第 ④ 步 `tick` 出手，持有 `hostAttack` 600 ms。
- **GIVEN** 敌将一阶段 steps 7 / 8，**WHEN** 连上一对火（申请 `effect` 380 ms），**THEN** 这一帧不调用 `tick`、不出手；令牌归还后的第一次 `tick` 才出手（如果那时 `hp > 0`）。
- **GIVEN** 敌将，**WHEN** 无操作喂入 600 帧（约 10 秒），**THEN** `tick` 被调用 600 次，敌将没有出手。
- **GIVEN** 敌将一阶段 hp = 1、有二阶段，**WHEN** 连上一对，**THEN** 点击后的结算点不进入“结束”；同一帧 `tick` 后持有 `phase` 令牌；之后 1400 ms 前台时间里 `gameTime` 不变、点击被丢弃；令牌到点后时钟恢复。
- **GIVEN** 开讲水牌、`slots = 3`、槽位为 [张飞（主将）, 关羽, 空]，**WHEN** 点“开讲”，**THEN** 武将技能收到出阵武将 [张飞, 关羽]；这一回结束时 `RoundResult.loadout = ['zhang_fei', 'guan_yu']`，`skillsUsed` 只有这两个键。
- **GIVEN** 开讲水牌按钮出现后 300 ms，**WHEN** 点一个技能槽，**THEN** 无反应；600 ms 时点击展开可选武将。
- **GIVEN** 一回打完回到结算卡，**WHEN** 点“再来一回”，**THEN** 水牌上的槽位是刚才的出阵阵容，仍可以换。
- **GIVEN** 敌将模式在二阶段输掉，**WHEN** 进入“结束”，**THEN** `RoundResult.bossPhase = 2`；粮草模式结束时 `bossPhase = null`。
- **GIVEN** 敌将 hp 已为 0、盘上剩下的块正好是死局，**WHEN** 到结算点，**THEN** 直接判胜，不洗牌。
- **GIVEN** 暂停卡开着，**WHEN** 切到后台再回来，**THEN** 仍显示暂停卡（接着讲、回书目两个按钮）。
- **GIVEN** 压境到点下压，**WHEN** 下压发生，**THEN** 盘面当场下移、不申请令牌，盘不锁；敌将出手时当场扣心和增兵，之后持有 `hostAttack` 600 ms。
- **GIVEN** 粮草模式 food = 1、盘上只剩 1 对火和 3 对营，**WHEN** 玩家消掉火，**THEN** 先扣粮到 0，效果演出 380 ms 后清掉营，到结算点时盘已空，`outcome()` 判胜。
- **GIVEN** 战场压力的 `outcome()` 被打桩为同时满足胜负，**WHEN** 检查，**THEN** 结果为胜利。
- **GIVEN** 敌将模式 hearts = 1，**WHEN** 敌将出手，**THEN** 600 ms 内状态仍是“对局”，演出结束后的结算点进入“结束（败）”，`reason = '城破'`。
- **GIVEN** 失败卡出现，**WHEN** 300 ms 时点“再来一回”，**THEN** 无反应；600 ms 时点击生效。
- **GIVEN** 胜利，**WHEN** 进入“结束”，**THEN** 界面在 2000 ms（`ENDING_WIN_MS`）后调用 `endingDone()`，之前状态一直是“结束”；失败时为 300 ms。
- **GIVEN** 胜利卡，**WHEN** 收尾完成、按钮出现后 300 ms 点击，**THEN** 无反应；按钮出现后 600 ms 点击生效。
- **GIVEN** 点了“开讲”，**WHEN** 遮罩渐出的 150 ms 内点盘，**THEN** 点击被丢弃，`gameTime` 为 0；渐出结束后点盘有效。
- **GIVEN** 一回结束，**WHEN** 进入“结束”，**THEN** 同一帧交出 `RoundResult`，字段齐全、类型正确，赢时 `reason` 为 null，`metrics` 的形状与模式一致。
- **GIVEN** 网址参数 `seed=42`、同一回目第 1 次开局，**WHEN** 刷新页面后再第 1 次开局，**THEN** 两次 `seed` 相同；**WHEN** 点“再来一回”，**THEN** `attempt = 2`，`seed` 不同。
- **GIVEN** 最后一回胜利，**WHEN** 结算卡出现，**THEN** 只有“再来一回”和“书目”。
- **GIVEN** 对局中点暂停印再点“回书目”，**WHEN** 回到书目，**THEN** 没有交出结果对象，存档不变。

## Open Questions

- 小红书 WebView 里可见性事件、`pagehide` 是否可靠？隐式后台的 1000 ms 阈值会不会被低端机的卡顿误触发？（负责：平台探测；目标：技术准备阶段的真机验证。）
- 关羽选排在**压境**模式里不停钟：选排期间可能到点下压甚至破城。要不要让选排在压境里也停钟（申请一个无时长令牌）？本文先按“不停钟”写，因为切片只验证过敌将模式。（负责：用户 + 关卡设计；目标：第二回重排前。）
- 选排时“点盘外 = 取消”里，盘外包括其他武将牌（点了只取消、不放技能）。要不要改成“点别的就绪武将 = 取消选排并直接放他”？本文按“只取消”写，少一种意外。（负责：试玩。）
- `ENDING_WIN_MS` 2000 里的闪白和手机震动，与美术圣经第 7 节“不震屏”是否冲突，待美术总监确认。（负责：art-director。）
- ADR-0002 的令牌清单需要加 `phase`；帧顺序不变（出手仍在 `tick` 里，只是触发条件换成步数）。（负责：technical-director；目标：架构复审。）
