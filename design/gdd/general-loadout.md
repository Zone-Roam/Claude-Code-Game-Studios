# 选将与解锁

> **Status**: In Review（2026-10-30 按 /design-review 修订，待复审）
> **Author**: 用户 + 主会话（lean 模式）
> **Last Updated**: 2026-10-30
> **Last Verified**: 2026-10-30
> **Implements Pillar**: 2 将在人为（挑谁上阵也是一个决定）、3 故事决定这一回打什么仗（主将由故事定）、5 攒得踏实（赢哪回得哪位武将）、4 一看就会（不挑也能直接开讲）

## Summary

每一回开讲前，水牌下面有一排技能槽（最多 3 个）。第一个槽是这一回的主将，由故事定，不能换；其余的槽从已解锁的武将里挑，槽位开局就按推荐阵容填好，不想挑的人直接点“开讲”。打赢哪一回，就得哪位武将。

> **Quick reference** — Layer: `Feature` · Priority: `Vertical Slice`（正式版前 10 回） · Key deps: `武将技能、回目编排与难度、进度、三星与存档、界面与交互`

## Overview

切片的第三次试玩里，用户提出想像植物大战僵尸那样，开局前把武将放进技能槽、自由组合（2026-10-29）。这和原来的支柱 3“出阵武将由故事决定”冲突，用户的取舍是：**故事定主将，其余槽自选**（2026-10-30）。这样每一回仍有它的故事主角，例如长坂坡一定有赵云，而“这一仗带谁去”成了开讲前的一个小决定，武将越攒越多，组合也越来越多。

这个系统做四件事：
- 从回目数据读出槽位数、主将和推荐阵容。
- 从进度推出已解锁的武将。
- 在水牌上让玩家换将。
- 把最终阵容交给武将技能系统，作为这一回的出阵武将。

它不改任何技能本身，技能由“武将技能”定义。

## Player Fantasy

“这一回吕布攻得快，带张飞压他的蓄力，再带赵云挡一招。”主帅在帐前点将：主将是故事给的，副将是自己挑的。挑对了，这一仗打得顺；挑错了，下次换一套再来。武将一位一位攒起来，每一位都是自己打下来的。

## Detailed Design

### Core Rules

**槽位与主将**

1. 每一回有 `slots` 个技能槽，取 1–3（回目数据字段，见“回目编排与难度”）。
2. 每一回有一位主将 `lead`（武将 id），占第 1 个槽，盖“主将”朱印，**不能换下**。
3. 每一回有推荐阵容 `recommend`（武将 id 列表，长度等于 `slots`，第一位必须是 `lead`）。它取代原来的 `generals` 字段。
4. 正式版的头几回只给 1–2 个槽，往后逐步开到 3 个。具体哪一回开几个槽，由关卡编排定，但同一回只引入一样新东西（支柱 4）：开第 2 个槽的那一回，不再同时登场新压力或新效果。
   - **例外**（用户决定 9，2026-10-30）：这一回可选武将的总数不超过 `slots`（规则 12，只显示、不展开换将）时，玩家没有东西可挑，开槽不算新东西。正式版第二回同时有敌将首登场和第 2 槽，可选只有关羽、张飞，按此例外。第五回同开第 3 槽和吕布二阶段，可选有四位，算两样新东西，用户接受。
   - **例外**（用户决定 D7，2026-10-30）：第三回同时出现三样新东西：第一次有展开的点将区（可选 3 位 > 2 槽）、层叠（registry 的 `new` 字段）、赵云首次当主将。保持这一关的设计，不拆；列入试玩观察清单（看新手在第三回是否卡在点将区或层叠上）。教学引导的“第一次出现可换的槽”提示（见 Interactions）正落在这一回，写教学 GDD 时要与此对齐。

**解锁**

5. 每一回可以写一个 `unlock`（武将 id）：**第一次**赢下这一回时，这位武将解锁。重打赢了不会再解锁别人。
6. 开局就有的武将写在数据文件的 `starters` 列表里，正式版是 `['guan_yu']`（只有关羽；用户决定，2026-10-30）。其余武将按回目解锁：第一回张飞、第三回赵云、第四回刘备、第七回诸葛亮、第八回黄忠（“回目编排与难度”规则 13）。
7. 已解锁的武将 = `starters` + 所有 `wins ≥ 1` 的回目的 `unlock`。存档里**不单独存**，每次从进度推出来（和回目解锁的做法一样，“进度、三星与存档”规则 10）。
8. 主将和推荐阵容里的武将，**这一回一律可用**，哪怕还没解锁（例如故事要求这回赵云登场，而赵云正是这回的奖励）。这一回赢了才正式解锁。

**点将**

9. 水牌下面显示一排槽位。**“再来一回”**：槽位原样沿用内存里刚才的状态，空槽也保持为空，不重新走下面的填法。**其他入口**（从书目进入、“下一回”、跨会话）按下面的顺序填到 `slots` 个，每一步都跳过已在槽里的武将（去重）：
   1. 先放这一回的主将 `lead`，占第 1 个槽（即使存档的 `loadout` 里主将不在首位或根本没有）；
   2. 再依次放这一回上次的阵容（规则 13）里的非主将武将，要求仍然可用（见规则 11 的“本回可用”）；
   3. 不够的位置，用推荐阵容里还没上阵的武将依次补上；
   4. 还不够，就空着。空槽不影响开讲。
   被玩家清空的副将槽，下次从别的入口进入时会按推荐补回；这是有意接受的代价（存档的 `loadout` 不存空位）。
10. **换将**：点一个非主将的槽，槽下面展开可选武将（仅当规则 12 的 `showPicker` 为真）。可选的是已解锁的武将，再加上规则 8 里这一回可用的武将，去掉已经在槽里的。点一位就把他放进这个槽；点槽里的“×”就把这个槽清空。
11. **不对路的武将**：这一回的 `deck` 里没有某位武将的蓄力兵时，这位武将**不算进 `available`**（不计入规则 12 的人数）。只有点将区**已经因为别的原因展开**（`showPicker` 为真）时，展开区才把 `unlocked ∪ recommend` 里这样的武将画成灰牌，写“此回无{兵}”（例如“此回无鼓”），不能选；`showPicker` 为假时不显示灰牌（对中老年玩家没有可挑的就不多出干扰，支柱 4）。
12. **不显示点将的情况**：`showPicker(ch) = ch.slots ≥ 2 且 |available(ch)| > ch.slots`。为假时（只有 1 个槽，或可选的武将总数不超过 `slots`）没什么可挑的，槽位直接按规则 9 填好，只显示、不展开换将。
13. **记住阵容**：每一回结算（`settle()`）时，把这一回实际上阵的武将 id 列表写进这一回的存档记录，字段名 `loadout`，长度 1–3，不含空位（主将槽不可空）。放弃的一回不写，和星级一样（“进度、三星与存档”规则 12）；`RoundResult.loadout` 为空（理论上不会发生）时也不写，保持旧值。
14. 点“开讲”的那一刻，槽里的武将（按槽位顺序，跳过空槽）作为这一回的出阵武将，由“对局流程与时钟”交给“武将技能”（再写进 `RoundResult.loadout`）。之后这一回里不能换将；“再来一回”沿用内存里刚才的槽位（空槽也保持），回到水牌时可以再换。

### States and Transitions

| 状态 | 进入 | 离开 |
|---|---|---|
| 未解锁 | 默认 | 赢下 `unlock` 是他的那一回；或者他在 `starters` 里 |
| 已解锁 | 见上 | 不会离开（输了不会重新上锁） |
| 本回可用（计入 `available`） | 已解锁，或是这一回的主将或推荐阵容里的人；并且 `deck` 里有他的蓄力兵。`deck` 里没有他的蓄力兵的人不算可用，只在点将区已展开时画成灰牌（规则 11） | 换到别的回目 |
| 上阵 | 在槽里时点了“开讲” | 这一回结束 |

### Interactions with Other Systems

- **对局流程与时钟**：点将发生在它的“开讲”状态；点“开讲”时由它把 `loadout` 转给武将技能，并写进 `RoundResult.loadout`（1–3 个）交给进度。
- **武将技能**：只读本系统交出的出阵武将列表。武将牌最多 3 张，顺序就是槽位顺序。本系统反过来读武将表里每位武将的蓄力兵（软依赖，用于判断 `deck` 里有没有）。
- **回目编排与难度**：提供 `slots`、`lead`、`recommend`、`unlock`、`starters`、`deck`。加载时的检查见 Edge Cases。
- **进度、三星与存档**：提供各回 `wins`（推出已解锁的武将），保存各回的 `loadout`。
- **界面与交互**：水牌上的点将区、可选武将的展开、变灰的提示、桌沿的武将牌改成最多 3 张。
- **教学引导**：第一次出现可换的槽时，提示一次“点空槽，挑一位武将”。

## Formulas

本系统不定义数值曲线，只有一条集合计算：

```
unlocked = starters ∪ { ch.unlock | ch 能加载，且 progress[ch.id].wins ≥ 1 }
available(ch) = (unlocked ∪ {ch.lead} ∪ ch.recommend) 中，蓄力兵在 ch.deck 里的武将
pickable(ch) = available(ch) − {ch.lead}
showPicker(ch) = ch.slots ≥ 2 且 |available(ch)| > ch.slots
grayCards(ch) = showPicker(ch) ? (unlocked ∪ ch.recommend) − available(ch) : ∅
```

`available` 里不含蓄力兵不在 `deck` 的武将，所以灰牌只在点将区已经展开时才显示（规则 11）。例：第九回 `deck` 有刀、盾、旗、书、弓，没有鼓；已解锁六位时 `available` = {关羽, 赵云, 刘备, 诸葛亮, 黄忠} = 5 位，多于 3 个槽，展开后张飞是灰牌，写“此回无鼓”。

例子：`starters = [关羽]`。
- 赢过第一回（`unlock` = 张飞），现在打第二回：`slots` = 2，`lead` = 张飞，`recommend` = [张飞, 关羽]。`available` = {关羽, 张飞}，2 位，不多于 2 个槽，不显示点将，槽位直接是张飞、关羽。
- 再打第三回：`slots` = 2，`lead` = 赵云（这回的奖励，按规则 8 可用），`deck` 里有刀、鼓、盾。`available` = {关羽, 张飞, 赵云}，3 位，多于 2 个槽，显示点将，副将从关羽、张飞里挑一位。

## Edge Cases

- **主将的蓄力兵不在这一回的 `deck` 里**：数据错误，这一回拒绝加载（主将必须能放技能）。
- **推荐阵容里有人的蓄力兵不在 `deck` 里**：只警告；填槽时跳过他。
- **`recommend` 长度不等于 `slots`，或第一位不是 `lead`**：拒绝加载。
- **`unlock` 写了一位已在 `starters` 里的武将**：只警告，赢了也不会多出什么。
- **两回的 `unlock` 是同一位武将**：只警告，以先赢下的那一回为准。
- **存档里的 `loadout` 有不认识的武将 id、重复的 id，或者长度超过这一回的 `slots`**：只丢掉 `loadout` 这一项，按推荐阵容填，这一回的星级和胜场照用（不按“进度、三星与存档”规则 11 整条丢掉）。
- **存档里的 `loadout` 有一位现在不可用的武将**（例如改版后他的蓄力兵从 `deck` 里拿掉了）：跳过他，按规则 9 补位。
- **存储不可用**：已解锁的武将只在这一次页面会话里有效，阵容不记住，和星级的兜底一样（“进度、三星与存档”规则 17）。
- **只有 1 个槽**：只有主将，不显示点将（`showPicker` 要求 `slots ≥ 2`），即使已解锁别的武将、`available` 多于 1 位也一样；水牌和切片一样只多一张主将牌。
- **槽里有空位时点开讲**：照常开讲，桌沿只摆有人的武将牌；`loadout` 只含有人的槽（至少主将 1 位）。
- **“再来一回”时槽里有空位**：原样保持为空，不按规则 9 补满（规则 14）。
- **存档的 `loadout` 里主将不在首位、或主将被重复放进两个槽**：规则 9 先放主将，再放其余，去重，不会出现主将占两槽。

## Tuning Knobs

| 参数 | 位置 | 默认 | 安全范围 | 影响 |
|---|---|---|---|---|
| `slots` | 每回数据 | 编排决定 | 1 到 `SLOT_MAX` | 槽越多越好打，挑选的讲究也越多 |
| `starters` | 数据文件顶层（数据归回目编排，本系统只读） | 1 位（关羽） | 1–3 位 | 开局手里有几位武将 |
| `unlock` | 每回数据 | 编排决定 | 每回 0–1 位 | 武将攒得多快 |
| `SLOT_MAX` | 常量 | 3 | 3（再多桌沿放不下大牌） | 槽位上限 |

## Acceptance Criteria

（以下按正式版前 10 回的数据写：`starters = [guan_yu]`；第一回 `slots 1`、`lead guan_yu`、`unlock zhang_fei`；第二回 `slots 2`、`lead zhang_fei`、`recommend [zhang_fei, guan_yu]`；第三回 `slots 2`、`lead zhao_yun`、`recommend [zhao_yun, guan_yu]`、`unlock zhao_yun`，`deck` 有刀、鼓、盾。见“回目编排与难度”规则 13。）

- **GIVEN** 存档为空、`starters = [guan_yu]`，**WHEN** 打开第一回的水牌，**THEN** 只显示一个关羽的主将槽，没有换将按钮。
- **GIVEN** 已解锁关羽、张飞，**WHEN** 重打第一回（`slots = 1`），**THEN** 只有关羽一个主将槽，没有换将按钮（`showPicker` 要求 `slots ≥ 2`）。
- **GIVEN** 第一回 `unlock = zhang_fei`，**WHEN** 第一次赢下第一回，**THEN** 已解锁的武将是关羽、张飞。
- **GIVEN** 第一回已赢过一次、已解锁关羽、张飞，**WHEN** 再赢一次，**THEN** 已解锁的武将不变。
- **GIVEN** 已解锁关羽、张飞，**WHEN** 第一次打开第二回，**THEN** 槽位是张飞（主将，不能换）和关羽，点第 2 个槽不展开（可选 2 位不多于 2 个槽，规则 12、规则 4 例外）。
- **GIVEN** 已解锁关羽、张飞，**WHEN** 第一次打开第三回，**THEN** 槽位是赵云（主将，不能换）和关羽；点第 2 个槽，可选的只有张飞。
- **GIVEN** 已解锁关羽、张飞，**WHEN** 打开第三回、把关羽换成张飞、输掉本回，再次打开第三回，**THEN** 槽位是赵云、张飞（输了也结算，写入 `loadout = ['zhao_yun','zhang_fei']`），且第三回星级与胜场不变。
- **GIVEN** 第一次赢下第三回（`unlock = zhao_yun`），**WHEN** 推出已解锁的武将，**THEN** 是关羽、张飞、赵云。
- **GIVEN** 已解锁六位武将，第九回 `slots = 3`、`deck` 有刀、盾、旗、书、弓，没有鼓（`available` = 关羽、赵云、刘备、诸葛亮、黄忠 = 5 > 3，`showPicker` 为真），**WHEN** 展开第 2 个槽，**THEN** 张飞的牌是灰牌，写“此回无鼓”，点了没有反应。
- **GIVEN** 已解锁关羽、张飞、赵云、刘备，第八回 `deck` 里没有旗（刘备、诸葛亮不在 `available`，`available` = 关羽、张飞、赵云 = 3，不多于 3 个槽），**WHEN** 打开第八回水牌，**THEN** `showPicker` 为假，不展开，也不显示任何灰牌；槽位按规则 9 填好。
- **GIVEN** 某回主将在存档的 `loadout` 里排第 2 位、或被重复放进两个槽，**WHEN** 从书目打开这一回，**THEN** 主将在第 1 槽，没有重复，其余按存档、推荐的顺序补位。
- **GIVEN** 3 槽的一回，玩家清空第 3 槽后开讲、结算，**WHEN** 点“再来一回”，**THEN** 水牌上第 3 槽仍是空的；**WHEN** 改为回书目再进入同一回，**THEN** 第 3 槽按推荐阵容补上。
- **GIVEN** 本回 `RoundResult.loadout` 为空数组（理论上不会发生），**WHEN** 结算，**THEN** 存档里这一回原有的 `loadout` 保持不变。
- **GIVEN** 某回 `lead` 的蓄力兵不在 `deck` 里，**WHEN** 游戏启动加载回目，**THEN** 这一回被拒绝加载，开发版控制台给出回目 id 和字段名 `lead`。
- **GIVEN** 存档里 ch03 的 `loadout` 是 `["zhao_yun", "lv_bu"]`（`lv_bu` 不是武将），**WHEN** 打开第三回，**THEN** 槽位按推荐阵容填（赵云、关羽），ch03 的星级照常显示。
- **GIVEN** 槽位是赵云和张飞，**WHEN** 点开讲，**THEN** 桌沿只有赵云、张飞两张武将牌，顺序和槽位一致，牌宽等于“界面与交互”`card_width` 公式在两张牌、当前屏宽下的结果（96–112 px），牌高 ≥ 72 px。
- **GIVEN** 存储不可用，**WHEN** 同一次会话里依次赢下第一回、第二回再打开第三回，**THEN** 展开第 2 槽，可选张飞。
