# 三国连连看：试玩调优经验

**时间**：2026-10-27（竖切片试玩）到 2026-10-31（上传小红书、配音效和 BGM）
**来源**：`production/trial-notes.md` 里所有“用户：”开头的行和第四部分补记，共 30 多次修改要求
**用途**：做下一个游戏时开工前读一遍；末尾的“工具改进候选”是要改进 CCGS skill 和模板的清单

一句话结论：skills 把设计、架构、任务、代码这条主线走得很顺，返工几乎都出在**“看得见、听得见、摸得着”的东西**上——美术风格、界面细节、声音手感、真机平台。这些东西文档写不出对错，只能靠用户眼睛和耳朵判断，所以要**更早拿出可比较的样品让用户挑**，而不是先按文档做完再改。

---

## 一、美术与界面（返工最多）

### 1. 风格要先定一张目标效果图，再写美术圣经

- **用户原话**：“风格是网站自带的吗……先多出几版，不要擅自做完整套 UI，太老土”；“和效果图差得远”。
- **发生了什么**：美术圣经先按文字定了风格，第 8 节还禁了回弹、弹出、发光、闪、震；按它做出来的界面被评“老土”。用户真正想要的是 Q 版卡通、暖木质感，有自己的效果图；切片里用户喜欢的击碎、暴怒震屏、翻牌弹出恰好都在禁用清单里。
- **下次怎么做**：写美术圣经**之前**，先出 3–4 张不同方向的整屏效果图（开始画面、对局、书目各一张），用户挑一张当目标图；美术圣经按这张图写，禁用清单只禁性能上真不能用的东西，手感类效果（震屏、弹出）等试玩后再定。之后每次改界面都和目标图并排对比。
- **该在哪检查**：`/art-bible` 开头；`/vertical-slice` 的界面部分。

### 2. 素材处理要按成熟做法，不能凑合

- **用户原话**：“抠的图不干净，边缘锯齿太多，学学成熟做法”。
- **原因**：EvoMeme 的透明图是品红底抠的，边缘带品红；我们又压成 256 色调色板 PNG、缩放时没做预乘。
- **下次怎么做**：AI 出的素材一律用正经抠图模型（这次用用户本机 ComfyUI 的 RMBG-2.0），缩放用预乘透明度的 Lanczos，保留完整透明通道；批量处理写成脚本（这次的 `pack_warm.py`），换素材时一键重打。
- **该在哪检查**：`/asset-spec` 的交付标准；美术圣经第 8 节。

### 3. 放位置要量，不要目测

- **用户原话**：“蓄力格没对上”。
- **原因**：卡框图上头像窗、名牌、金槽的位置是目测的百分比。
- **下次怎么做**：拿到带“窗口”的素材，先在图上画网格量出各区域的实际范围，再按量出的数写样式；截图放大检查对齐。

### 4. 休闲手游有一张“完整感”清单，要早过

用户陆续提出的这些，单看都不大，但每一条都要等试玩才冒出来：

- 开始界面（“再做一个开始游戏界面”）
- 每关背景跟剧情走（“随机背景？最好和关卡有关”）
- 每个角色都有头像，包括敌方（“做 Q 版敌将”）
- 同类元素一样大（“三个技能槽应该一样大”）
- 状态变化一眼看得出（“充能完成不明显”）
- 进度条、计时条不能糙（“倒计时条糙”）
- 字和元素的大小按目标人群（老年人）定（“棋子太小”“叠字太大”）

**下次怎么做**：把这张清单放进界面审查，第一个可玩版本出来就逐条过一遍，而不是等用户一条条提。

### 5. 改界面时给对比稿，用户挑

- 这次技能卡改了好几轮（A/B/C 都不满意，换思路做 D/F，选 D）。**有效的做法**：先在 EvoMeme 出一张组件素材表，再做几个并排的版本让用户挑；挑定后把没选的样式全部删掉。

## 二、玩法与难度

### 6. 第一关就要有一点难度，生成规则不能让人一眼看穿

- **用户原话**：“第一回每排都是成对的，没难度，想加重力”；第二次试玩“变简单了”。
- **下次怎么做**：关卡生成要检查“相邻就是一对”这类一眼可见的规律；难度手段（层叠、下落、拆对）至少有一种从第一关就生效。
- **注意**：“找得到找不到”这种难度，模拟器和 `/balance-check` 都量不出来（机器人能看到所有对子），只能靠试玩。

### 7. 切片阶段边试边改规则是常态，要有轻量通道

- 用户在切片阶段提了二阶段吕布、击碎特效、层叠、选将等，规则大改了几次；模板的 `/vertical-slice` 只有 PROCEED/PIVOT/KILL，PIVOT 要求回去改 GDD 再做切片，太重。
- **有效的做法**：一页改动单放在切片目录，切片验证后再统一合进 GDD；改数值就重跑模拟，数值结论和规则一起记版本。

## 三、声音与手感（最后一天集中暴露）

### 8. 音效、震动、按下反馈是 MVP 必做，不是“完整版”

- **用户原话**（第一次真机试玩）：“没有声音，没有音效，也没有按键反馈”。
- **原因**：立项时 game-concept 写“Audio：MVP 不做”，音效系统排在完整版；按钮没有按下样式；震动只写了两处高潮，还用的是网页接口。
- **下次怎么做**：手机休闲游戏的 MVP 必须包含：点按音、成功音、失败音、开场音、背景音乐、静音开关、所有可按元素的按下样式、轻震动（走宿主平台接口）。

### 9. 音效直接用真实录音，并且先拿同类游戏做基准

- **用户原话**：“音效有点闷，合成感重”；“不太像连连看的手感”。
- **发生了什么**：先用 Web Audio 现场合成（被嫌闷）；换 Kenney 真实录音但挑得太短太尖（被嫌不像连连看）；最后下载开源连连看的音效量了一下——选中约 0.3 秒的中音“嘀”，配对约 0.1 秒的圆“啵”——按这个特征挑候选，用户一次选定。
- **下次怎么做**：
  1. 一开始就用 CC0 真实录音（Kenney 的 Interface / Impact / UI / RPG Audio / Music Jingles 五个包够用），不要合成。
  2. 先找 2–3 个同类游戏，量出它们关键音效的时长、音高、亮度，作为挑选基准。
  3. 做本地试听页，候选和参考并排，用户按编号挑（这次 T5/P2/M4 一次定）。
- **工具**：`scratchpad` 里的 `analyze_sfx.py`（时长、重心、起音）、`dom.py`（主频）、`pack_sfx.py`（去静音、归一、转 MP3、写 base64 模块）——下次应该放进 `tools/audio/`。

### 10. BGM 要早定来源和体积

- EvoMeme 的音乐生成标着“敬请期待”，让创作工作室做只交回一页说明，**这条路暂时不通**。
- 免费曲库能用：OpenGameArt 上 CC0 和 CC-BY 的中国风曲子不多但够挑；CC-BY 要在游戏里署名。
- 无缝循环要按整小节切、接缝做交叉淡化，并对照原曲检查接缝处的跳变是不是原曲本来就有（这次的 `make_loop.py`、`seam_check.py`）。
- 两段 BGM 约 0.9 MB，原来的 2 MB 包体放不下，用户放宽到 3 MB。**下次立项定包体预算时就把音乐算进去**（平台实际允许 zip 10 MB）。

## 四、平台与发布

### 11. 第一个可玩版本就上真机

- 上传小红书时才发现：平台禁止内联 `<script>`（要拆成外部 js）、`localStorage` 不保证可靠（推荐宿主存储 API）、震动要用宿主的 `vibrateShort`、音频文件不能放进包。平台探测页（`tools/platform-probe/`）写好了但一直没在真机上跑。
- 声音缺失这个最大的问题，也是第一次真机扫码才被发现。
- **下次怎么做**：第一个能玩的版本就上传平台、扫码真机试玩；平台文档（这次是 `miniapp-sandbox.xiaohongshu.com/minitool/doc`）在写架构时就读，结论写进 `docs/engine-reference/<平台>/VERSION.md`。

### 12. 发布要一条命令，不靠手敲

- 出过两个错：构建参数写成 `release`（应为 `--release`），之前上传的几版其实是开发版；构建脚本被 `.gitignore` 的通用 `[Bb]uild/` 规则忽略、从没进仓库。
- 小红书发布还要手工拆脚本、打 zip、上传后重新点“不需要权限”（重新上传会把它清掉）。
- **下次怎么做**：构建脚本加平台目标（如 `node tools/build/build.mjs --release --target xhs`），一步完成构建、拆脚本、打 zip、检查是发布版和体积；仓库初始化时检查构建脚本有没有被忽略。

## 五、协作方式

### 13. 问得太碎会急人，能批量就批量

- **用户原话**：“卧槽，究竟还要多久啊”（拆史诗时每个都单独问“建不建”“写不写”，用户每次都选是）。
- **下次怎么做**：同类决定一次问完；用户全选推荐的那类问题（建不建史诗、写不写文件）在 `guided` 模式下直接做、事后汇报。

### 14. 选项要做成能看、能听的样品，用户按编号回答

这次最省时间的做法，下次照用：

- 图标三选一的对比图、技能卡 A–F 并排、音效试听页（T1–T6、P1–P6、M1–M4、S1–S10、B1–B10）。
- 用户回复“T5/P2/M4”就能定，不用描述感受。
- 用户说“你自己挑吧”时，按可量化的指标挑（节奏密度、时长、亮度），并说明理由。

### 15. 共用浏览器窗口要收拾干净

- **用户原话**：“这玩个毛啊，都挡住了”——我在共用浏览器窗口里用控制台把卡片栏放大了 3 倍检查对齐，没刷新就交回去了。
- **下次怎么做**：控制台改页面只当临时检查，检查完一律刷新、复原视口；改过本地存储（如静音开关）也要还原。

## 六、做得好的，继续保持

- skills 主线（概念 → GDD → 架构 → ADR → 史诗 → 任务 → 代码 → 测试）走得顺，写代码的实际用时远低于估计。
- 草稿只写暂存区、主会话合并冲突再挑问题给用户：用户只看要点，不用读几万字草稿。
- 用户的参考图上传到 EvoMeme 当风格参考，出图明显更贴近。
- 每一步记进 `production/trial-notes.md`，这份经验文档就是从它整理出来的。
